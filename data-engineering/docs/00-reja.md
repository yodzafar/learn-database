# Data Engineering rejasi: platforma, modellashtirish, batch, streaming va ekspluatatsiya

Nima uchun bu modul eng muhimlaridan biri: data engineering ma'lumotni manbadan (OLTP baza, API, fayl, hodisa oqimi) olib, ishonchli, tekshirilgan, arzon va so'rov qilinadigan holatga keltirish muhandisligi. Analytics, BI, ML va AI mahsulotlari shu poydevorga tayanadi: dashboard, model yoki agent sifati pipeline sifatidan oshmaydi. Bu modul DE ning yagona asosiy rejasi: arxitektura, modellashtirish (Inmon, Kimball, Data Vault), analitik SQL, fayl va table formatlar, warehouse va query enginelar, Spark, ingestion va CDC, Kafka va stream processing, orkestratsiya, dbt, sifat va governance, cloud stack, DataOps, FinOps va system design intervyu. Har bosqichda lokal docker laboratoriyada amaliyot bor.

Boshqa modullar bilan chegara:
- `../sql/` va `../theory/`: SQL asoslari, tranzaksiya, indeks, query plan shu yerda takrorlanmaydi, faqat analitik (OLAP) tomoni chuqurlashtiriladi.
- `../postgres/`, `../mysql/`, `../mssql/`, `../oracle/`, `../mongodb/`: vendor CDC mexanizmi (PostgreSQL logical decoding va replication slot, MySQL binlog va GTID, SQL Server CDC va Change Tracking, Oracle LogMiner) o'sha modulda chuqur. Bu yerda Debezium, Kafka Connect va pipeline tomoni chuqur.
- `../clickhouse/`: ClickHouse ichki tuzilishi chuqur o'sha yerda. Bu yerda u warehouse va real-time OLAP tanlash kontekstida.
- `../../learn-python/data/docs/00-reja.md`: Python kodi (pandas, Polars, PySpark DataFrame API, dlt) dasturlash nuqtai nazaridan o'sha yerda chuqur. Bu yerda platforma, SQL, arxitektura, asboblar va end-to-end tizim. Ikkalasi parallel o'tilsa eng yaxshi natija beradi, lekin bu modul o'zi mustaqil.
- `../projects/`: 8, 9, 10-loyihalar shu modulning yakuniy imtihoni.

Boshlash: `../sql/` I–IV bosqichlari (JOIN, aggregatsiya, window function, CTE), `../theory/` dan tranzaksiya va indeks asoslari, `../postgres/` I–II bosqichi. Python I–III (`../../learn-python/`) yoki Go asoslari (`../../learn-golang/`): skript yozish, `uv`, virtual muhit. Docker va `docker compose` bilan ishlash (`make up`, `make shell`). Kafka va Spark bosqichlariga kirishdan oldin `../theory/` dagi replication va partitioning mavzulari tavsiya etiladi.

## I bosqich: Landshaft va arxitektura

1. **DE roli, karyera va kasb xaritasi**: data engineer vs analytics engineer vs data platform engineer vs ML engineer vs data analyst vs data scientist (kim nimani yozadi, kim nimaga javobgar, qaysi asboblar), "Type A" (SQL/analytics) va "Type B" (software/platform) data engineer, junior/middle/senior/staff darajalari va kutilmalar, vakansiya talablarini o'qish (Spark, Airflow, dbt, Kafka, cloud kombinatsiyalari), DE ning biznes qiymati (ishonchli metrika, ML ga ma'lumot, regulyator hisobotlari), stakeholder bilan ishlash va talab yig'ish (kim iste'molchi, qanday SLA, qanday freshness), "data team topologiyalari" (markazlashgan, embedded, hub-and-spoke), Uzbekistan va xalqaro bozorda DE talabi, bu modul va `../projects/` qanday portfolio beradi
2. **Data engineering lifecycle va undercurrents**: Reis va Housley modeli: generation (manba tizimlari), storage, ingestion, transformation, serving (analytics, ML, reverse ETL); undercurrents: security (least privilege, encryption at rest/in transit), data management (governance, sifat, lineage, master data), DataOps (avtomatlashtirish, observability, incident response), data architecture (reversible decision'lar, "two-way door"), orchestration, software engineering (test, versiya, code review); manba tizimini tushunish (OLTP sxema, API cheklovlari, event'lar, log'lar), ma'lumot hajmi, tezligi va xilma-xilligi (volume/velocity/variety), freshness, latency, completeness va accuracy SLA/SLO, "data downtime" tushunchasi, build vs buy qarori, vendor lock-in
3. **OLTP vs OLAP va ishlov berish paradigmalari**: OLTP (qator-orientirli, ko'p kichik yozish, normalizatsiya, indeks) va OLAP (columnar, katta skan, aggregatsiya, denormalizatsiya) nega bitta bazada sig'maydi, HTAP urinishlari (TiDB, SingleStore, Snowflake Unistore, PostgreSQL + columnar extension) va chegarasi, read replica'dan analytics qilish tuzog'i, batch vs micro-batch vs stream (latency, narx, murakkablik trade-off), ETL vs ELT vs EtLT (yengil tozalash ingestion'da, og'ir transformatsiya warehouse'da), push vs pull ingestion, full vs incremental, idempotency va determinizm pipeline'ning birinchi qonuni sifatida, "exactly once" ning amaliy ma'nosi
4. **Arxitekturalar: lake, warehouse, lakehouse, mesh**: klassik enterprise data warehouse (Inmon CIF, Kimball bus), data lake (schema-on-read, "data swamp" xavfi), lakehouse (object storage + open table format + ko'p engine), medallion (bronze/silver/gold) va uning layer'lari qanday kontrakt beradi, Lambda arxitektura (batch layer + speed layer + serving, ikki kod bazasi muammosi), Kappa arxitektura (faqat log va replay), streaming-first lakehouse, data mesh (domain ownership, data as a product, self-serve platform, federated governance) va qachon tashkiliy ortiqchalik, data fabric (metadata-driven integratsiya, virtualizatsiya), modern data stack (Fivetran/Airbyte + Snowflake/BigQuery + dbt + BI) va post-modern holati, reference arxitekturalar (a16z, AWS/Azure/GCP well-architected), arxitektura qarorini ADR bilan hujjatlash
5. **Lokal DE laboratoriyasi**: `docker compose` profillari (`minio`, `trino`, `spark`, `kafka`, `flink`, `airflow`, `iceberg-rest`, `connect`, `superset`), har servisning roli va porti, MinIO (S3 API, bucket, `mc` CLI), Iceberg REST catalog, Trino catalog konfiguratsiyasi (`etc/catalog/*.properties`), manba OLTP sifatida PostgreSQL va namunaviy dataset (TPC-H/TPC-DS generatori `duckdb` `dbgen`/`dsdgen`, NYC Taxi, ochiq e-commerce dataset), `uv` bilan Python muhit (`dbt-duckdb`, `dbt-postgres`, `dbt-trino`, `pyiceberg`, `confluent-kafka`, `pyspark`), RAM va CPU budjeti arm64'da, `make up`/`make down`/`make shell`, servis sog'lig'ini tekshirish (`healthcheck`), ma'lumotni qayta yaratish skripti (reproducible lab), `.env` va secret'lar git'dan tashqarida
