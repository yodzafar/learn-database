# MySQL rejasi: InnoDB ichki tuzilishidan stored programs, replikatsiya va ekspluatatsiyagacha

Nima uchun alohida va chuqur: MySQL dunyodagi eng ko'p deploy qilingan ochiq relyatsion baza (WordPress, Facebook, GitHub, Shopify, Uber, Booking tarixan unga tayangan). Uning xulq-atvori PostgreSQL'dan ko'p joyda farq qiladi: server layer va pluggable storage engine ajratilgan, InnoDB clustered index (jadval = primary key bo'yicha B+tree), default `REPEATABLE READ` va gap/next-key lock'lar, `sql_mode` ga bog'liq "jim" ma'lumot buzilishi, `utf8` aslida 3 baytli `utf8mb3`, replikatsiya binlog asosida (fizik WAL emas, mantiqiy log). Bu farqlarni bilmasdan MySQL'da ishlagan backend dasturchi deadlock, yo'qolgan ma'lumot va sekin so'rovlarga duch keladi. Bu modul MySQL'ni dasturchi (stored programs, JSON, optimizer) va DBA (replikatsiya, backup, online DDL, tuning) ko'zi bilan yoritadi.

Boshlash: `theory/` I–III bosqich (relyatsion model, tranzaksiya, isolation anomaliyalari, B-tree va WAL), `sql/` I–III bosqich (DDL/DML, JOIN, aggregatsiya, subquery, CTE va window standart ko'rinishi). Standart SQL bu yerda takrorlanmaydi: faqat MySQL dialekti va farqlari. `postgres/` I–II bosqichdan keyin o'tilsa solishtirish ancha foydali bo'ladi, lekin shart emas.

Ishlash tartibi: `mysql/docs/NN-slug.md` nazariya va vazifalar, kod `mysql/NN-slug/main.sql` (yoki `task_N.sql`) va `test.sql` (MyTAP). Ishga tushirish: `make up db=mysql` (konteyner `ldb-mysql`, MySQL 8.4 LTS), `make shell db=mysql` (interaktiv `mysql` CLI), `make my n=01` (papkadagi `main.sql` ni bajarish), `make my-test n=01` (MyTAP testlari), `make reset db=mysql` (bazani toza holatga qaytarish). Replikatsiya va cluster mavzularida (V bosqich) compose'da qo'shimcha `ldb-mysql-replica` va Group Replication uchun 3 tugunli profil ishlatiladi, dars buni aniq aytadi. Lint: `sqlfluff lint --dialect mysql`. `make check` topshirishdan oldin toza bo'lishi shart. Stored program yozilganda `DELIMITER` faqat `mysql` CLI direktivasi ekanini unutmang: fayl CLI orqali bajariladi, shuning uchun `main.sql` da `DELIMITER //` ishlatiladi.

## I bosqich: Arxitektura va asoslar

1. **MySQL arxitekturasi va o'rnatish**: tarix (MySQL AB, Sun, Oracle, MariaDB fork, Percona Server), versiya modeli (8.4 LTS, 9.x Innovation relizlari, 8.0 EOL aprel 2026), server layer (connection handling, parser, optimizer, query cache yo'qolgani 8.0 da) va storage engine API (InnoDB, MyISAM, MEMORY, CSV, ARCHIVE, `SHOW ENGINES`), thread-per-connection modeli va thread pool (Enterprise/Percona), `max_connections` narxi, konteynerda ishga tushirish (`mysql:8.4` image, `MYSQL_ROOT_PASSWORD`, `/docker-entrypoint-initdb.d`), `mysql` CLI (`-e`, `--table`, `\G`, `source`, `pager`, `--login-path` va `mysql_config_editor`), MySQL Shell `mysqlsh` (`\sql`, `\js`, `\py` rejimlari, `util`, `dba` obyektlari), konfiguratsiya fayllari va o'qilish tartibi (`my.cnf`, `--print-defaults`, `SET PERSIST`, `mysqld-auto.cnf`), `SHOW VARIABLES`/`SHOW STATUS`, session vs global o'zgaruvchilar, `information_schema`, `performance_schema`, `sys`, `mysql` sistem bazalari, data directory tuzilishi (`.ibd`, `ibdata1`, `#innodb_redo`, `undo_001`, binlog fayllar), `mysqld --initialize`, DBeaver va VS Code ulanish
2. **InnoDB ichki tuzilishi**: tablespace'lar (system, file-per-table `innodb_file_per_table`, general, undo, temporary), sahifa (16KB default, `innodb_page_size`), extent va segment, clustered index (qator = PK B+tree bargida, PK bo'lmasa birinchi `NOT NULL UNIQUE`, u ham bo'lmasa yashirin 6 baytli `DB_ROW_ID`), secondary index bargida PK qiymati (nega uzun PK hamma indeksni kattalashtiradi, nega random UUID PK insert'ni sekinlashtiradi va `UUID_TO_BIN(uuid, 1)`), yashirin ustunlar `DB_TRX_ID`/`DB_ROLL_PTR`, buffer pool (LRU young/old sublist, `innodb_buffer_pool_size`, instances, dump/load on restart), change buffer (secondary index o'zgarishlarini kechiktirish), adaptive hash index, doublewrite buffer (torn page himoyasi), redo log (`innodb_redo_log_capacity` 8.0.30+, LSN, checkpoint, `innodb_flush_log_at_trx_commit` 0/1/2 va durability trade-off), undo log (rollback va MVCC, purge thread, history list length), row formatlari (`DYNAMIC`, `COMPACT`, `COMPRESSED`, off-page `TEXT`/`BLOB`), `innodb_ruby` yoki `INFORMATION_SCHEMA.INNODB_*` bilan ko'rish, MyISAM qachon hali uchraydi va nega ishlatilmaydi (table lock, crash safe emas)
3. **Ma'lumot tiplari va sql_mode tuzoqlari**: butun sonlar (`TINYINT`...`BIGINT`, `UNSIGNED`, display width `INT(11)` eskirgani), `DECIMAL(p,s)` vs `FLOAT`/`DOUBLE`, `BOOLEAN` = `TINYINT(1)` taxallusi, `CHAR`/`VARCHAR` (bayt vs belgi chegarasi, 65535 qator limiti), `TEXT`/`BLOB` oilasi va indekslash cheklovi, `ENUM`/`SET` (ichki raqam, tartib tuzog'i, qachon lookup jadval yaxshi), `DATE`/`DATETIME`/`TIMESTAMP` (TIMESTAMP 2038 muammosi va time zone konvertatsiyasi, `DATETIME(6)` mikrosekund, `DEFAULT CURRENT_TIMESTAMP ON UPDATE`), `YEAR`, `BIT`, `BINARY`/`VARBINARY`, `JSON` (IV bosqichda chuqur), spatial tiplar, `sql_mode` (`STRICT_TRANS_TABLES`, `ONLY_FULL_GROUP_BY`, `NO_ZERO_DATE`, `ERROR_FOR_DIVISION_BY_ZERO`, `NO_ENGINE_SUBSTITUTION`, `ANSI_QUOTES`, `PIPES_AS_CONCAT`), non-strict rejimda "jim" truncate va `0000-00-00`, `SHOW WARNINGS`, implicit type conversion tuzoqlari (`'abc' = 0`, string ustunni son bilan solishtirish indeksni o'ldiradi), `CAST`/`CONVERT`, time zone jadvallari va `CONVERT_TZ`, `@@time_zone`
4. **Charset va collation**: `utf8mb3` vs `utf8mb4` (emoji va 4 baytli belgilar, nega `utf8` dan qochish kerak), charset darajalari (server, baza, jadval, ustun, connection: `character_set_client`/`connection`/`results`, `SET NAMES`), collation turlari (`utf8mb4_0900_ai_ci` 8.0 default, `_as_cs`, `_bin`, `utf8mb4_general_ci` va `unicode_ci` farqi), accent/case sensitivity, PAD SPACE vs NO PAD (oxirgi bo'shliq tuzog'i), collation nomosligi xatosi (`Illegal mix of collations`) va JOIN'da indeks ishlamay qolishi, `COLLATE` ifodada, `utf8mb4` va indeks uzunligi chegarasi (3072 bayt, eski 767), latin1'dan utf8mb4 ga migratsiya (`ALTER TABLE ... CONVERT TO`, double-encoding muammosi va tuzatish), o'zbek/kirill matn saralash, `WEIGHT_STRING` bilan collation'ni ko'rish
5. **DDL, constraints va AUTO_INCREMENT**: `CREATE TABLE` variantlari (`IF NOT EXISTS`, `LIKE`, `AS SELECT`, `TEMPORARY`), PK tanlash (surrogate `BIGINT AUTO_INCREMENT` vs natural vs UUID, ordered UUID), `UNIQUE`, `FOREIGN KEY` (faqat InnoDB, `ON DELETE/UPDATE CASCADE/SET NULL/RESTRICT`, FK uchun avtomatik indeks, `foreign_key_checks=0` xavfi, FK va ALTER cheklovlari), `CHECK` (8.0.16 gacha e'tiborsiz qolgani, `ENFORCED`/`NOT ENFORCED`), `DEFAULT` ifodalar (8.0.13+), `AUTO_INCREMENT` ichki tuzilishi (`innodb_autoinc_lock_mode` 0/1/2, bo'shliqlar, 8.0 da restartdan keyin saqlanishi, replikatsiyaga ta'siri, `auto_increment_increment/offset`), invisible columns (8.0.23), atomic DDL (8.0, data dictionary InnoDB'da) va DDL implicit commit, `RENAME TABLE` atomar almashtirish, `TRUNCATE` vs `DELETE`, metadata lock (MDL) va uzun tranzaksiya ALTER'ni qanday bloklashi
6. **MySQL SQL dialekti va DML xususiyatlari**: `INSERT ... ## II bosqich: Tranzaksiya, locking, indeks va optimizer

7. **Tranzaksiyalar va MVCC**: `START TRANSACTION`, `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `autocommit` va uning tuzog'i (ORM va pool), implicit commit qiladigan buyruqlar ro'yxati, consistent read va read view (`START TRANSACTION WITH CONSISTENT SNAPSHOT`), read view qachon yaratiladi (RR'da birinchi SELECT'da, RC'da har statement'da), undo zanjiri orqali eski versiyani qurish, uzun tranzaksiya va history list length o'sishi (purge lag, disk va tezlik), `information_schema.INNODB_TRX`, `performance_schema.events_transactions_current`, `innodb_lock_wait_timeout` va timeout'da faqat statement rollback bo'lishi (`innodb_rollback_on_timeout`), read-only tranzaksiya (`START TRANSACTION READ ONLY`) optimizatsiyasi, XA tranzaksiyalar qisqa
8. **Isolation darajalari amalda**: to'rt daraja va `transaction_isolation`, `REPEATABLE READ` da snapshot read vs current (locking) read farqi (`SELECT` vs `SELECT ... FOR UPDATE`/`UPDATE` boshqa ma'lumotni ko'radi), phantom: snapshot read'da yo'q, locking read'da next-key lock bilan yo'q, lekin "UPDATE keyin SELECT" anomaliyasi, write skew misoli va uni `FOR UPDATE` bilan oldini olish, lost update va `SELECT ... FOR UPDATE`/optimistic locking (version ustun), `READ COMMITTED` ga o'tish sabablari (kamroq gap lock, replikatsiya ROW format bilan), `SERIALIZABLE` da oddiy SELECT ham `LOCK IN SHARE MODE` bo'lishi, `READ UNCOMMITTED` qachon ham kerak emas, ikki session bilan anomaliyalarni qo'lda takrorlash (`theory/` dagi anomaliyalar jadvali bilan solishtirish)
9. **InnoDB locking va deadlock**: shared/exclusive lock, intention lock (IS/IX), record lock, gap lock, next-key lock, insert intention lock, auto-inc lock, qaysi so'rov qaysi lock'ni oladi (unique indeks bo'yicha teng qidiruv vs diapazon vs indekssiz ustun = butun jadval skanida hamma qator lock), `SELECT ... FOR UPDATE NOWAIT` va `SKIP LOCKED` (8.0, navbat jadvali patterni), `FOR SHARE`, `LOCK TABLES` va nega ishlatmaslik, metadata lock, deadlock aniqlash (`innodb_deadlock_detect`, `SHOW ENGINE INNODB STATUS` LATEST DETECTED DEADLOCK bo'limini o'qish, `innodb_print_all_deadlocks`), `performance_schema.data_locks` va `data_lock_waits`, `sys.innodb_lock_waits`, deadlock'ni kamaytirish (bir xil tartibda lock olish, qisqa tranzaksiya, to'g'ri indeks), ilovada retry (1213 xato kodi)
10. **Indekslar**: B+tree tuzilishi InnoDB'da, clustered vs secondary va "double lookup", covering index (`Using index`), composite indeks va leftmost prefix qoidasi, ustun tartibi (tenglik birinchi, diapazon oxirida), index condition pushdown (`Using index condition`), prefix indeks (`VARCHAR(255)` uchun `col(20)`, selectivity hisoblash), functional indeks (8.0.13, `((LOWER(email)))`), invisible indeks (o'chirishdan oldin sinash), descending indeks (8.0), skip scan (8.0.13), FULLTEXT indeks (InnoDB, `MATCH ... AGAINST`, natural/boolean mode, `ngram` parser), SPATIAL indeks, hash indeks yo'qligi (MEMORY dan tashqari), duplicate va unused indekslarni topish (`sys.schema_redundant_indexes`, `sys.schema_unused_indexes`), indeks narxi (yozish, buffer pool), `ANALYZE TABLE` va `innodb_stats_persistent`, kardinallik
11. **EXPLAIN va bajarilish rejasi**: `EXPLAIN` ustunlari (`type`: system/const/eq_ref/ref/range/index/ALL, `possible_keys`, `key`, `key_len` ni o'qib qaysi ustunlar ishlatilganini aniqlash, `rows`, `filtered`, `Extra`: Using where/index/temporary/filesort/join buffer), `EXPLAIN FORMAT=TREE` va `FORMAT=JSON` (cost), `EXPLAIN ANALYZE` (8.0.18, haqiqiy vaqt va qatorlar), `EXPLAIN FOR CONNECTION`, join algoritmlari (nested loop, block nested loop o'rniga hash join 8.0.18), semijoin strategiyalari (`FirstMatch`, `LooseScan`, `Materialization`, `DuplicateWeedout`), derived table merge vs materialization, `ORDER BY ... LIMIT` va filesort, `GROUP BY` uchun indeks, `OR` va index merge, sekin so'rovni bosqichma-bosqich tuzatish misollari
12. **Optimizer ichki tuzilishi, hints va histogram**: cost model (`mysql.server_cost`, `engine_cost`), statistika va namuna olish (`innodb_stats_persistent_sample_pages`), histogram (`ANALYZE TABLE ... UPDATE HISTOGRAM ON col WITH N BUCKETS`, singleton vs equi-height, `information_schema.COLUMN_STATISTICS`, indekssiz ustunda kardinallik bahosi), optimizer trace (`SET optimizer_trace="enabled=on"`, `information_schema.OPTIMIZER_TRACE` ni o'qish), `optimizer_switch` flaglari, index hints (`USE/FORCE/IGNORE INDEX`), optimizer hints `/*+ ... */` (`JOIN_ORDER`, `INDEX`, `NO_INDEX`, `HASH_JOIN`, `SET_VAR`, `MAX_EXECUTION_TIME`, `SEMIJOIN`, `BKA`, `MRR`), query rewrite plugin, hint qachon to'g'ri yechim va qachon texnik qarz
13. **Sahifalash, katta jadval va so'rov patternlari**: `LIMIT offset` muammosi va keyset (seek) pagination, deferred join, `COUNT(*)` InnoDB'da nega sekin va taxminiy hisob (`information_schema.TABLES.TABLE_ROWS`), `SQL_CALC_FOUND_ROWS` deprecated, batch `UPDATE`/`DELETE` (`LIMIT` bilan bo'lib, replikatsiya lag'ini kamaytirish), katta `IN` ro'yxat va `range_optimizer_max_mem_size`, `ORDER BY RAND()` muqobillari, N+1 va ORM, top-N per group (window bilan, IV bosqichga havola), queue jadval `SKIP LOCKED` bilan, soft delete va unique indeks muammosi, hot row contention (counter jadval shardlash)
14. **Temporary jadvallar va ichki xotira**: user temporary table (`CREATE TEMPORARY TABLE`, session doirasi, replikatsiya bilan munosabat), internal temporary table (`Using temporary`), TempTable engine (8.0, `temptable_max_ram`, `temptable_max_mmap`), on-disk ga o'tish va `Created_tmp_disk_tables`, `sort_buffer_size`, `join_buffer_size`, `tmp_table_size`, per-connection buferlar va nega ularni katta qilish xavfli (max_connections bilan ko'paytiriladi), memory instrumentatsiya (`sys.memory_by_thread_by_current_bytes`)

ON SCHEDULE EVERY 1 DAY STARTS ...`, `AT`, `ON COMPLETION PRESERVE`, `ENABLE`/`DISABLE ON SLAVE` (8.4 da `DISABLE ON REPLICA`), event ichida procedure chaqirish, partition rotation va eski ma'lumot tozalash event bilan, event xatolarini kuzatish), views (`CREATE OR REPLACE VIEW`, `ALGORITHM=MERGE/TEMPTABLE/UNDEFINED`, updatable view shartlari, `WITH CHECK OPTION` `LOCAL`/`CASCADED`, view ichida `ORDER BY`), `SQL SECURITY DEFINER` bilan huquqni cheklash (foydalanuvchi jadvalga emas, view/procedure'ga ega), `DEFINER` foydalanuvchi o'chirilsa nima bo'ladi (orphan definer), `SET_USER_ID` va `SYSTEM_USER` privilege 8.0, stored program'larni dump qilish (`--routines --events --triggers`)
23. **Stored programs'ni testlash, debug va versiyalash**: MyTAP o'rnatish va asosiy funksiyalar (`plan`, `ok`, `is`, `isnt`, `has_table`, `has_column`, `col_type_is`, `has_procedure`, `has_function`, `has_trigger`, `results_eq`, `throws_ok`, `finish`), test faylini tranzaksiya ichida yozish va `ROLLBACK`, fixture ma'lumot, `make my-test`, debug usullari (MySQL'da interaktiv debugger yo'q: log jadvali, `SELECT` bilan debug chiqishi, `SIGNAL` bilan to'xtatish, `performance_schema.events_statements_history` da routine ichidagi statement'lar, `sys.ps_trace_thread`), procedure ichidagi so'rovlar uchun `EXPLAIN` qanday olinadi, routine'larni git'da saqlash va migratsiya bilan deploy (idempotent `DROP ... IF EXISTS` + `CREATE`, `ops/` moduliga havola), sqlfluff bilan lint, kod uslubi va nomlash konvensiyasi (`sp_` prefiksidan qochish emas, MySQL'da muammo yo'q, lekin izchillik)

## IV bosqich: Zamonaviy imkoniyatlar

24. **JSON chuqur**: `JSON` tipi (binar format, validatsiya, 1GB `max_allowed_packet` chegarasi), path sintaksisi (`$.a.b[0]`, `$**`), `->` va `->>` (`JSON_UNQUOTE(JSON_EXTRACT())`), `JSON_OBJECT`, `JSON_ARRAY`, `JSON_ARRAYAGG`, `JSON_OBJECTAGG`, `JSON_SET`/`JSON_INSERT`/`JSON_REPLACE`/`JSON_REMOVE`, partial update (in-place, binlog'da `binlog_row_value_options=PARTIAL_JSON`), `JSON_CONTAINS`, `JSON_OVERLAPS`, `MEMBER OF`, `JSON_SEARCH`, `JSON_TABLE` (JSON'ni relyatsion jadvalga, `NESTED PATH`, `FOR ORDINALITY`), `JSON_SCHEMA_VALID` va CHECK constraint bilan sxema, generated column orqali JSON maydonni indekslash, multi-valued index (8.0.17, `CAST(... AS UNSIGNED ARRAY)`), qachon JSON ustun va qachon normal jadval (EAV anti-pattern bilan solishtirish), MySQL Document Store va X DevAPI qisqa
25. **Generated columns va functional patternlar**: `GENERATED ALWAYS AS (...) VIRTUAL` vs `STORED`, virtual ustunga secondary indeks, deterministik ifoda talabi, JSON maydondan, sana qismidan, `LOWER()` dan ustun, functional indeks bilan farqi (ichida yashirin virtual ustun), generated column va `INSERT` cheklovlari, CHECK bilan birga, hisoblangan ustunni ilovaga ko'chirish o'rniga bazada saqlash qachon to'g'ri
26. **CTE, window va analytic so'rovlar MySQL'da**: 8.0 dan `WITH` va `WITH RECURSIVE` (`cte_max_recursion_depth`, ierarxiya va sana ketma-ketligi generatsiyasi), window funksiyalar (`ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`/`LEAD`, `FIRST_VALUE`, `NTH_VALUE`, `NTILE`, `PERCENT_RANK`, `CUME_DIST`, frame), MySQL'ga xos cheklovlar (window `RANGE` bilan interval, `WINDOW` clause, `QUALIFY` yo'qligi), 5.7 uslubidagi user variable hack'larni window bilan almashtirish, CTE materialization va `EXPLAIN`, top-N per group va running total MySQL'da unumdorligi (standart semantika `sql/` modulida, bu yerda faqat dialekt va optimizer)
27. **Partitioning**: `RANGE`, `RANGE COLUMNS`, `LIST`, `HASH`, `KEY` partitioning, subpartition, partition key PK/unique tarkibida bo'lishi shart qoidasi, partition pruning va `EXPLAIN` da `partitions` ustuni, partition boshqaruvi (`ADD`, `DROP`, `REORGANIZE`, `EXCHANGE PARTITION`, `TRUNCATE PARTITION`), vaqt bo'yicha rotation event bilan, partitioning qachon foyda (ma'lumot o'chirish, arxivlash) va qachon zarar (FK yo'q, ko'p partition ochish narxi, global indeks yo'q), native partitioning 8.0 (InnoDB ichida), sharding bilan farqi (VII bosqich Vitess)

## V bosqich: Replikatsiya va yuqori mavjudlik

28. **Binary log**: binlog maqsadi (replikatsiya va PITR), formatlar `STATEMENT`/`ROW`/`MIXED` va nega `ROW` default, `binlog_row_image` (`FULL`/`MINIMAL`/`NOBLOB`), `mysqlbinlog` bilan o'qish (`--base64-output=DECODE-ROWS -vv`), binlog event turlari, `sync_binlog=1` va `innodb_flush_log_at_trx_commit=1` ("double one" durability), binlog group commit, `binlog_expire_logs_seconds`, `SHOW BINARY LOGS`, `FLUSH BINARY LOGS`, 2PC: redo log va binlog o'rtasidagi ichki XA, binlog'ni CDC uchun o'qish (Debezium, Maxwell, Canal: `data-engineering/` ga havola), binlog compression (`binlog_transaction_compression`)
29. **Asinxron va semi-sinxron replikatsiya**: source/replica terminologiyasi (8.4 da `MASTER`/`SLAVE` buyruqlari olib tashlangan: `CHANGE REPLICATION SOURCE TO`, `START REPLICA`, `SHOW REPLICA STATUS`), replikatsiya oqimi (dump thread, IO/receiver thread, relay log, SQL/applier thread), GTID (`gtid_mode=ON`, `enforce_gtid_consistency`, `gtid_executed`, `gtid_purged`, `SOURCE_AUTO_POSITION=1`), position-based vs GTID, multi-threaded replica (`replica_parallel_workers`, `replica_preserve_commit_order`, WRITESET dependency tracking), replication lag (`Seconds_Behind_Source` nega yolg'on, `pt-heartbeat`), semi-sync (`rpl_semi_sync_source_enabled`, AFTER_SYNC lossless, timeout'da async'ga tushish), `super_read_only` replikada, replikatsiya filtrlari va xavfi, multi-source replikatsiya (kanallar), delayed replica (`SOURCE_DELAY`), replikatsiyani buzish va tiklash (skip transaction GTID bilan, `pt-table-checksum`/`pt-table-sync` bilan konsistentlik), konteynerda source + 2 replika qurish
30. **Group Replication**: Paxos asosidagi guruh (XCom), single-primary vs multi-primary, certification va konflikt aniqlash, flow control, guruhga qo'shilish va distributed recovery (clone plugin bilan), `group_replication_consistency` (EVENTUAL, BEFORE, AFTER, BEFORE_AND_AFTER), split-brain va quorum, `performance_schema.replication_group_members`, cheklovlar (har jadvalda PK, InnoDB, katta tranzaksiya limiti), 3 tugunli guruhni konteynerda qurish va bitta tugunni o'ldirib failover kuzatish, `theory/` dagi consensus bilan bog'lash
31. **InnoDB Cluster, ClusterSet va MySQL Router**: MySQL Shell AdminAPI (`dba.configureInstance`, `dba.createCluster`, `cluster.addInstance`, `cluster.status()`, `cluster.setPrimaryInstance`), InnoDB ReplicaSet (async, sodda), ClusterSet (DR uchun boshqa data center'dagi cluster), MySQL Router (read/write split portlari 6446/6447, metadata cache, bootstrap), clone plugin (`CLONE INSTANCE FROM`), switchover va failover sinovi, ilova tomonidan ulanish (Router orqali, connection retry)
32. **Proxy, read/write split va sharding**: ProxySQL (query rules, hostgroups, read/write split, connection multiplexing, query caching, failover bilan ishlash, admin interfeysi), HAProxy oddiy TCP balansi, ilova darajasida read-after-write konsistentlik muammosi (replika lag), Orchestrator (topologiya va avtomatik failover tarixi), Vitess (VTGate, VTTablet, keyspace, vindex, resharding, YouTube/Slack/GitHub tarixi), PlanetScale g'oyasi (branching, non-blocking schema change), application-level sharding va uning narxi, qachon sharding kerak va qachon vertikal o'sish yetadi (`newsql/` va `theory/` ga havola)

## Mezon

Har mavzu: `main.sql` `make my n=NN` bilan xatosiz bajariladi va `make reset db=mysql` dan keyin qayta bajarilganda ham bir xil natija beradi (idempotent: `DROP ... IF EXISTS`), `sqlfluff lint --dialect mysql` toza, stored program yozilgan har mavzuda `test.sql` MyTAP testlari (muvaffaqiyatli va xato yo'li) o'tadi, locking/isolation vazifalarida ikki session ketma-ketligi kommentda vaqt bo'yicha yozilgan, indeks/optimizer vazifalarida `EXPLAIN ANALYZE` oldin va keyin natijasi kommentda va "nega" izohi bilan.
