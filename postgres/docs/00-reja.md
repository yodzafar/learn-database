# PostgreSQL rejasi: arxitekturadan PL/pgSQL, replikatsiya va production ekspluatatsiyagacha

Nima uchun alohida va eng chuqur modul: PostgreSQL bugun backend va data engineering'da eng ko'p tanlanadigan ochiq relatsion baza. U standart SQL'ga eng yaqin, kengaytiriladigan (o'z tiplari, indeks turlari, PL tillari, extension'lar), va ichki tuzilishi ochiq hujjatlangan. Shuning uchun loyihada `sql/` modulidagi standart SQL ham shu yerda ishga tushiriladi, `theory/` dagi MVCC, WAL, B-tree nazariyasi esa shu modulda aniq implementatsiya sifatida ko'riladi (`xmin`/`xmax`, `pg_wal`, `pageinspect`). Bu modulni yaxshi bilgan odam boshqa vendorlarni (MySQL, SQL Server, Oracle) "farqlar" orqali tez o'zlashtiradi.

Boshlash: `theory/` I–II bosqich (relatsion model, tranzaksiya, isolation anomaliyalari) va `sql/` I–III bosqich (DDL/DML, join, aggregatsiya, subquery, CTE, window). Ular tugamasdan bu modulning I–III bosqichini boshlash mumkin, lekin IV bosqich (PL/pgSQL) dan oldin `sql/` to'liq tugagan bo'lishi kerak. `theory/` dagi storage va indeks mavzulari II–III bosqich bilan parallel o'tiladi.

Ishlash tartibi: dars `postgres/docs/NN-slug.md`, kod `postgres/NN-slug/main.sql` (yoki `task_N.sql`), testlar `postgres/NN-slug/test.sql` (pgTAP). Ishga tushirish: `make up db=postgres` (bir marta), `make pg n=07` (`main.sql` ni `ldb-postgres` konteynerida `psql -v ON_ERROR_STOP=1` bilan bajaradi), testlar `make pg-test n=07`, interaktiv `make shell db=postgres`, toza holat `make reset db=postgres`. Lint: `sqlfluff` dialekt `postgres`. Har vazifa natijasi va "nega shunday" izohi SQL komment (`--`) sifatida faylda yoziladi. Replikatsiya, Patroni, PgBouncer mavzularida qo'shimcha profil (`postgres-replica`, `pgbouncer`) ishlatiladi, dars buni aytadi.

## Boshqa DBlar bilan solishtirish

| Mavzu | PostgreSQL | MySQL (InnoDB) | SQL Server | Oracle |
|---|---|---|---|---|
| Jarayon modeli | har ulanishga bitta OS jarayoni (`postmaster` fork) | bitta jarayon, thread per connection | bitta jarayon, SQLOS scheduler | jarayonlar va thread'lar (OS'ga qarab), dedicated/shared server |
| MVCC | eski versiyalar jadvalning o'zida (heap), VACUUM tozalaydi | undo log, purge thread | tempdb version store (RCSI/SNAPSHOT yoqilsa) | undo tablespace |
| Clustered index | yo'q, heap + `CLUSTER` bir martalik | PK doim clustered | ixtiyoriy clustered index | IOT (index-organized table) ixtiyoriy |
| Procedural til | PL/pgSQL (+ PL/Python, PL/Perl, PL/v8) | SQL/PSM uslubidagi stored program | T-SQL | PL/SQL (paketlar bilan) |
| Funksiya ichida COMMIT | faqat `PROCEDURE` da (11+) | procedure'da mumkin | procedure'da mumkin | procedure'da mumkin, autonomous transaction ham |
| DDL tranzaksiyada | ha, deyarli hammasi | yo'q (implicit commit) | ha, ko'pchiligi | yo'q (implicit commit) |
| Default isolation | Read Committed | Repeatable Read | Read Committed (lock-based) | Read Committed |
| Serializable | SSI (optimistik) | lock-based | lock-based | aslida snapshot isolation |
| Partitioning | declarative (range/list/hash) | range/list/hash/key | partition function/scheme | eng boy (interval, reference, composite) |
| Replikatsiya | streaming (fizik) + logical | binlog asosida, GTID, Group Replication | Always On AG, log shipping | Data Guard, GoldenGate |
| Kengaytirish | extension (tip, indeks, til) | plugin (cheklangan) | CLR | cartridge, Java |

## I bosqich: Arxitektura va asoslar
1. **Arxitektura**: `postmaster` va fork qilingan backend jarayonlar (nega thread emas, ulanish narxi va pooling zaruriyati), yordamchi jarayonlar (checkpointer, background writer, WAL writer, autovacuum launcher va worker'lar, stats, logical replication launcher, archiver, walsender/walreceiver, PG18 da io worker'lar), shared memory (`shared_buffers`, WAL buffers, lock table, CLOG/`pg_xact`), backend local xotira (`work_mem`, `maintenance_work_mem`, `temp_buffers`), OS page cache bilan ikki marta keshlash, `PGDATA` tuzilishi (`base/`, `global/`, `pg_wal/`, `pg_xact/`, `postgresql.conf`, `pg_hba.conf`, `postmaster.pid`), cluster/database/schema/object ierarxiyasi, `oid` va `relfilenode`, `pg_stat_activity` bilan jarayonlarni ko'rish, `ps` bilan konteyner ichida jarayon nomlari
2. **O'rnatish va psql chuqur**: rasmiy Docker image va `POSTGRES_*` env, PG18 da volume yo'li o'zgarishi, `initdb` va locale/collation (ICU vs libc, `pg_database.datcollate`), `psql` meta-buyruqlari (`\l`, `\dn`, `\dt+`, `\d+`, `\df+`, `\sf`, `\ef`, `\dx`, `\du`, `\dp`, `\x auto`, `\timing`, `\watch`, `\gset`, `\gexec`, `\crosstabview`, `\copy` vs `COPY`, `\i`, `\ir`, `\o`, `\set ON_ERROR_STOP`, `\if`), `.psqlrc`, `-v` o'zgaruvchilar va `:'var'` interpolatsiya, connection string va `PGSERVICE`/`.pgpass`, GUI asboblar (pgAdmin, DBeaver, DataGrip) qisqa, `pg_settings` va `SHOW`/`SET`/`ALTER SYSTEM`, parametr kontekstlari (`postmaster`, `sighup`, `user`) va `pg_reload_conf()`
3. **Tiplar I: son, matn, vaqt, identifikator**: `smallint`/`integer`/`bigint` va overflow, `numeric(p,s)` (aniq, sekin, pul uchun) vs `real`/`double precision`, `money` nega ishlatilmaydi, `serial` vs `GENERATED ALWAYS/BY DEFAULT AS IDENTITY` va sequence (`nextval`, `setval`, cache, bo'shliqlar nega normal), `text` vs `varchar(n)` vs `char(n)` (unumdorlik farqi yo'q), collation va `ORDER BY` natijasi, `citext` ga havola, `bytea` (hex format), `boolean` va uch qiymatli mantiq, `date`/`time`/`timestamp` vs `timestamptz` (nega doim `timestamptz`, `TimeZone` sessiya parametri, DST tuzoqlari), `interval` arifmetikasi va `justify_*`, `uuid` va `gen_random_uuid()`, PG18 da `uuidv7()` va nega vaqt bo'yicha tartiblangan UUID indeksga yaxshi, tip o'tkazish (`::`, `CAST`, implicit/assignment cast'lar), `pg_typeof`, `pg_column_size`
4. **Tiplar II: murakkab va maxsus tiplar**: array (`int[]`, `ARRAY[...]`, `unnest`, `array_agg`, `ANY`/`ALL`, `@>`/`&&`, 1 dan boshlanadigan indeks, ko'p o'lchamli, qachon array o'rniga jadval), `json` vs `jsonb` (kirish, chuqur 32-mavzuda), range va multirange (`int4range`, `tstzrange`, `[)` chegaralar, `&&`, `@>`, `range_agg`), `enum` (`CREATE TYPE ... AS ENUM`, qiymat qo'shish, o'chirib bo'lmasligi, qachon lookup jadval yaxshiroq), composite type va qator tiplari (`ROW(...)`, `(t).field`), `domain` (`CHECK` bilan qayta ishlatiladigan tip), network tiplar (`inet`, `cidr`, `macaddr`, `<<=`), geometric tiplar (`point`, `box`, `polygon`) va PostGIS dan farqi, `xml`, `tsvector` ga havola, `pg_type` katalogi, o'z base type'ini yaratish faqat C da ekanligi
5. **DDL va constraint'lar**: `CREATE TABLE` variantlari (`LIKE`, `INHERITS` va nega eskirgan, `UNLOGGED`, `TEMP` va `ON COMMIT`), `NOT NULL`, `CHECK` (ustun va jadval darajasi), `UNIQUE` va `NULLS NOT DISTINCT` (15+), `PRIMARY KEY`, `FOREIGN KEY` (`ON DELETE/UPDATE CASCADE/SET NULL/RESTRICT/NO ACTION` farqi, `MATCH FULL`, FK ustunida indeks kerakligi), `EXCLUDE USING gist` (bron qilish oralig'i kesishmasin), `DEFERRABLE INITIALLY DEFERRED` va `SET CONSTRAINTS`, `NOT VALID` + `VALIDATE CONSTRAINT` (katta jadvalda lock'siz qo'shish), PG18 da `NOT ENFORCED` va temporal `WITHOUT OVERLAPS`/`PERIOD` constraint'lar, generated columns (`STORED`, PG18 da `VIRTUAL` default), `ALTER TABLE` qaysi biri jadvalni qayta yozadi (rewrite) va qaysi biri faqat katalogni o'zgartiradi, `ACCESS EXCLUSIVE` lock va `lock_timeout`, schema va `search_path` xavfsizligi, `COMMENT ON`

## II bosqich: Ichki tuzilish
7. **Fizik saqlash**: relation fayllar va segmentlar (1 GB), fork'lar (main, `_fsm`, `_vm`, `_init`), 8 KB page tuzilishi (page header, line pointer massivi, bo'sh joy, tuple'lar), heap tuple header (`t_xmin`, `t_xmax`, `t_ctid`, `t_infomask`, null bitmap), `ctid` va nega u doimiy identifikator emas, alignment va ustun tartibi bilan joy tejash (`pg_column_size`), `fillfactor`, TOAST (2 KB chegara, `PLAIN`/`EXTENDED`/`EXTERNAL`/`MAIN` strategiyalari, `pglz` vs `lz4` siqish, `default_toast_compression`), `pageinspect` extension (`get_raw_page`, `heap_page_items`, `page_header`), `pg_relation_size`/`pg_total_relation_size`/`pg_indexes_size`, tablespace'lar va qachon kerak
8. **MVCC implementatsiyasi**: transaction ID (`xid`, 32-bit, `txid_current()`/`pg_current_xact_id()`), tuple ko'rinish qoidalari (`xmin` commit bo'lganmi, `xmax` bo'shmi), snapshot (`xmin`, `xmax`, `xip` ro'yxati, `pg_current_snapshot()`), CLOG/`pg_xact` va commit status, hint bits va nega birinchi `SELECT` ham yozadi, `UPDATE` = yangi tuple + eski tuple'ni `xmax` bilan belgilash (in-place emas), `DELETE` faqat belgilaydi, subtransaction'lar (`SAVEPOINT`) va `pg_subtrans` narxi (64 dan ortiq subxact overflow), multixact (`FOR SHARE` va ko'p locker), Read Committed da har statement yangi snapshot, Repeatable Read da tranzaksiya boshidagi snapshot, uzoq tranzaksiya nega butun klasterga zarar (`backend_xmin`), `pageinspect` bilan versiyalarni ko'zda ko'rish vazifalari
9. **VACUUM, autovacuum, freeze va wraparound**: dead tuple va bloat, `VACUUM` nima qiladi (dead tuple'larni bo'shatish, FSM va visibility map yangilash, indekslarni tozalash) va nima qilmaydi (faylni kichraytirmaydi), `VACUUM FULL` (jadvalni qayta yozadi, `ACCESS EXCLUSIVE`) va `pg_repack` alternativasi, `ANALYZE`, visibility map (all-visible, all-frozen) va index-only scan bilan bog'liqligi, autovacuum ishga tushish formulasi (`autovacuum_vacuum_threshold` + `scale_factor` * `reltuples`, insert-triggered vacuum 13+), jadval darajasida sozlash (`ALTER TABLE ... SET (autovacuum_vacuum_scale_factor = ...)`), cost-based delay, xid wraparound (2^31 chegarasi, `age(relfrozenxid)`, `autovacuum_freeze_max_age`, aggressive vacuum, "database is not accepting commands" falokati), freeze, PG16–17 da VACUUM xotira va unumdorlik yaxshilanishlari, PG18 da eager freezing, `pg_stat_user_tables` (`n_dead_tup`, `last_autovacuum`), `pg_stat_progress_vacuum`, bloat'ni o'lchash (`pgstattuple`)
10. **HOT update va bloat boshqaruvi**: Heap-Only Tuple (indekslangan ustun o'zgarmasa va page'da joy bo'lsa indeks yangilanmaydi), HOT chain va page pruning, `fillfactor` ni kamaytirib HOT ulushini oshirish, `pg_stat_user_tables.n_tup_hot_upd`, indekslar ko'pligi yozishni sekinlashtirishi (write amplification) va ishlatilmagan indekslarni topish (`pg_stat_user_indexes.idx_scan = 0`), indeks bloat va `REINDEX CONCURRENTLY`, "update-heavy" jadval dizayni (tez o'zgaradigan ustunlarni alohida jadvalga ajratish), Uber'ning Postgres'dan MySQL'ga o'tish maqolasi va unga javoblar (write amplification bahsi)
11. **WAL, checkpoint va crash recovery (PG implementatsiyasi)**: WAL yozuvlari va LSN (`pg_current_wal_lsn()`, `pg_walfile_name`), `pg_wal/` segmentlari (16 MB), full-page writes va torn page muammosi, `wal_level` (`minimal`, `replica`, `logical`), `synchronous_commit` (`on`/`off`/`local`/`remote_write`/`remote_apply`) va nima yo'qotiladi, `fsync`, `wal_sync_method`, group commit (`commit_delay`), checkpoint (`checkpoint_timeout`, `max_wal_size`, `checkpoint_completion_target`, "checkpoints are occurring too frequently" ogohlantirishi), background writer, crash recovery qanday REDO qiladi, `pg_waldump` bilan WAL'ni o'qish, `pg_stat_wal` va `pg_stat_checkpointer` (17+), WAL compression, `UNLOGGED` jadval va crash'dan keyin bo'shashi

## V bosqich: Concurrency
30. **Locking**: table-level lock rejimlari (8 ta: `ACCESS SHARE` dan `ACCESS EXCLUSIVE` gacha) va mosliklar jadvali, qaysi buyruq qaysi lockni oladi, row-level lock'lar (`FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR SHARE`, `FOR KEY SHARE`) va FK tekshiruvi bilan bog'liqligi, `NOWAIT` va `SKIP LOCKED`, lock queue va "DDL kutayotgan bitta `ALTER` hamma `SELECT` larni to'xtatadi" tuzog'i, `lock_timeout` va `statement_timeout`, `idle_in_transaction_session_timeout`, deadlock (aniqlash, `deadlock_timeout`, log'dagi xabarni o'qish, tartib bilan oldini olish), `pg_locks` va `pg_blocking_pids()` bilan kim kimni bloklayotganini topish, lightweight lock va wait event'lar (`pg_stat_activity.wait_event_type`)

## Ataylab kiritilmagan
PostgreSQL manba kodiga hissa qo'shish va C'da extension yozish chuqur (faqat `pgrx` kirish), Postgres-XL/Greenplum kabi fork'lar ichki tuzilishi, Kubernetes operatorlarini chuqur sozlash (`../ops/` va `../learn-golang` K8s bosqichi), Windows'da o'rnatish. Standart SQL (join, window, CTE, rekursiv so'rovlar) `../sql/` da, umumiy nazariya (MVCC, B-tree, WAL, ARIES) `../theory/` da, migratsiya asboblari va CI `../ops/` da, ilovadan drayver va ORM bilan ishlash `../app/` da. Kerak bo'lsa alohida so'rang.

## Mezon
Har mavzu: `main.sql` `make pg n=NN` bilan xatosiz bajariladi (`ON_ERROR_STOP`), qayta ishga tushirilsa ham ishlaydi (idempotent: `DROP ... IF EXISTS` yoki alohida schema), `sqlfluff lint` toza, IV bosqichdan boshlab har funksiya/procedure/trigger uchun pgTAP testi bor va `make pg-test n=NN` o'tadi. Indeks va tuning vazifalarida "oldin/keyin" `EXPLAIN (ANALYZE, BUFFERS)` natijasi komment sifatida faylda va xulosa bitta gap bilan. Ichki tuzilish vazifalarida `pageinspect`/katalog so'rovi bilan isbot. Mavzu "tugadi" degani: vazifalar bajarilgan, men tekshirganman, va siz mavzuni o'z so'zingiz bilan tushuntira olasiz.
