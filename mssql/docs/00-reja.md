# SQL Server rejasi: T-SQL to'laqonli, ichki tuzilish, unumdorlik va ekspluatatsiya

Nima uchun alohida va chuqur: Microsoft SQL Server korporativ dunyoda (bank, davlat tizimlari, ERP, .NET ekotizimi, O'zbekistonda ham ko'p tizimlar) eng ko'p uchraydigan tijoriy relyatsion baza. T-SQL boshqa dialektlardan ancha "dasturlash tili"ga yaqin: batch, o'zgaruvchilar, `TRY/CATCH`, table-valued funksiyalar va parametrlar, `MERGE`, `OUTPUT`, `APPLY`. Engine o'zi ham o'ziga xos: default holatda lock asosidagi `READ COMMITTED` (o'quvchi yozuvchini bloklaydi), clustered index tanlovi, parameter sniffing, tempdb hamma narsaning markazi, Query Store va Intelligent Query Processing. Bu modul SQL Server'ni T-SQL dasturchisi (procedure, funksiya, trigger, xato boshqaruvi, test), performance muhandisi (plan, indeks, statistika, wait stats) va DBA (backup, Always On, security, Agent) ko'zi bilan to'liq yoritadi.

Boshlash: `theory/` I–III bosqich (relyatsion model, tranzaksiya, isolation anomaliyalari, B-tree, WAL va recovery), `sql/` I–III bosqich (DDL/DML, JOIN, aggregatsiya, subquery, CTE va window standart semantikasi). Standart SQL bu yerda takrorlanmaydi: faqat T-SQL dialekti, uning qo'shimchalari va engine xulqi. `postgres/` yoki `mysql/` ning I–II bosqichi o'tilgan bo'lsa locking va MVCC farqi ancha aniq ko'rinadi.

Ishlash tartibi: `mssql/docs/NN-slug.md` nazariya va vazifalar, kod `mssql/NN-slug/main.sql` (yoki `task_N.sql`) va `test.sql` (tSQLt). Ishga tushirish: `make up db=mssql` (konteyner `ldb-mssql`, SQL Server 2022 Developer edition), `make shell db=mssql` (interaktiv `sqlcmd`), `make ms n=01` (papkadagi `main.sql` ni `sqlcmd -i` bilan bajarish, `GO` batch ajratgich sifatida ishlaydi), `make ms-test n=01` (tSQLt testlari), `make reset db=mssql`. Klientlar: `sqlcmd` (go-sqlcmd, `brew install sqlcmd`), VS Code `mssql` extension yoki DBeaver (Azure Data Studio 2026-yil fevralda iste'moldan chiqarilgan, ishlatilmaydi), SSMS faqat Windows'da (VM bo'lsa ixtiyoriy). Lint: `sqlfluff lint --dialect tsql`. `make check` topshirishdan oldin toza bo'lishi shart. Always On va log shipping mavzularida compose'da qo'shimcha `ldb-mssql2` va `ldb-mssql3` profili ishlatiladi.

Har mavzu: `main.sql` `make ms n=NN` bilan xatosiz bajariladi va qayta bajarilganda ham bir xil natija beradi (idempotent: `DROP ... IF EXISTS`, `CREATE OR ALTER`), `sqlfluff lint --dialect tsql` toza, procedure/funksiya/trigger yozilgan har mavzuda `test.sql` tSQLt testlari o'tadi (muvaffaqiyatli va xato yo'li, `ExpectException` bilan), har procedure standart xato shablonidan foydalanadi (`SET XACT_ABORT, NOCOUNT ON` va TRY/CATCH, `THROW`), concurrency vazifalarida ikki session ketma-ketligi kommentda vaqt bo'yicha yozilgan, unumdorlik vazifalarida oldin/keyin `SET STATISTICS IO, TIME ON` natijasi va actual plan'dagi asosiy operator kommentda "nega" izohi bilan. HA/DR vazifalarida topologiya skript bilan qayta quriladi va failover/restore isbotlangan. Mavzu "o'rganildi" deyilishi uchun men tekshirib tasdiqlaganman va siz o'z so'zingiz bilan tushuntira olasiz.
