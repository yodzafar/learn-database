# MongoDB rejasi: document model, aggregation, server-side logika, replikatsiya va sharding

Nima uchun alohida va muhim: MongoDB eng ko'p ishlatiladigan document DB va ko'p backend jamoalarning "default NoSQL" tanlovi. U relational dunyodan boshqacha fikrlashni talab qiladi: sxema ilova tomonidan boshqariladi, ma'lumot so'rov shakliga qarab joylashtiriladi (embed vs reference), JOIN o'rniga denormalizatsiya va `$lookup`, stored procedure o'rniga aggregation pipeline va ilova kodi. Noto'g'ri modellashtirilgan MongoDB (unbounded array, har narsa alohida collection, shard key xatosi) relational DB'dan ham sekinroq va qimmatroq ishlaydi. Bu reja shuni oldini oladi: BSON va WiredTiger ichki tuzilishidan boshlab aggregation pipeline, transaction, change stream, replica set va sharding'gacha.

Boshlash: `theory/` I–III bosqichlari (relational model, tranzaksiya va izolyatsiya, indeks ichki tuzilishi: B-tree) va `sql/` I–II bosqichlari tavsiya etiladi, chunki har mavzuda SQL bilan solishtiriladi. JavaScript'ni yaxshi bilasiz: `mongosh` to'liq JS REPL, bu sizning eng katta ustunligingiz. Replikatsiya va sharding (VI–VII bosqich) uchun `theory/` dagi replication, partitioning, consensus mavzulari oldin o'tilgan bo'lsin.

Ishlash tartibi: `mongodb/docs/NN-nom.md` nazariya va vazifalar, kod `mongodb/NN-slug/main.js` (`mongosh` skripti) va `test.js` (`assert` bilan: `assert.eq`, `assert.strictEqual`, `assert(cond, msg)`; mongosh ichida Node `assert` moduli `require("assert")` orqali ham ishlaydi). Ma'lumot `seed.js` bilan generatsiya qilinadi, katta dataset git'ga kirmaydi.

```
make up db=mongodb          # ldb-mongodb konteyneri (replica set rs0, bitta node: transaction va change stream uchun shart)
make shell db=mongodb       # interaktiv mongosh
make mongo n=05             # mongodb/05-*/main.js ni ishga tushirish
make mongo-test n=05        # mongodb/05-*/test.js
make reset db=mongodb       # volume'ni o'chirib toza boshlash
make check                  # barcha modullar testlari
```

Sharding (VII bosqich) uchun alohida compose profili ishlatiladi (`make up db=mongodb-sharded`: config server replica set, 2 shard, mongos). Atlas'ga oid mavzular (Search, Vector Search, Triggers) Atlas bepul M0 klasteri yoki `mongodb/mongodb-atlas-local` docker image bilan, faqat aniq ruxsat bilan.

## Boshqa DBlar bilan solishtirish

| Mavzu | PostgreSQL / relational | MongoDB | Cassandra | DynamoDB |
|---|---|---|---|---|
| Ma'lumot birligi | qator (row), qat'iy sxema | BSON hujjat, moslashuvchan sxema | partition ichidagi qatorlar | item (atributlar) |
| Sxema | DDL, `ALTER TABLE` | ixtiyoriy `$jsonSchema` validator | CQL jadval sxemasi qat'iy | faqat kalit atributlar qat'iy |
| JOIN | to'liq, optimizer bilan | `$lookup` (cheklangan), asosan embed | yo'q, denormalizatsiya | yo'q, single-table design |
| Tranzaksiya | to'liq ACID | bitta hujjat atomar; multi-document 4.0+ (narxi bor) | LWT (Paxos), bitta partition | `TransactWriteItems` (100 itemgacha) |
| Stored procedure | PL/pgSQL, T-SQL, PL/SQL | yo'q: aggregation pipeline, `$function`/`$accumulator` (JS), Atlas Functions | UDF/UDA (Java) | yo'q: Streams + Lambda |
| Trigger | DB ichida | change streams (ilova), Atlas Triggers | Java trigger (kam ishlatiladi) | Streams + Lambda |
| Indeks | B-tree, GIN, GiST, BRIN | B-tree (WiredTiger), multikey, text, 2dsphere, wildcard | primary key, SAI | GSI, LSI |
| Masshtablash | asosan vertikal + read replica | sharding o'rnatilgan (mongos) | leaderless ring | to'liq boshqariladi |
| Konsistentlik | kuchli | sozlanadi: write/read concern | sozlanadi: consistency level | eventual yoki strongly consistent read |

## I bosqich: Asoslar va arxitektura
1. **Document model va MongoDB'ning o'rni**: hujjat, collection, database ierarxiyasi, relational jadval va qator bilan xaritasi, "data that is accessed together should be stored together" tamoyili, sxema ilovada degani nimani anglatadi va nima uchun "schemaless" atamasi noto'g'ri, MongoDB qachon to'g'ri tanlov (o'zgaruvchan atributli katalog, content management, event/log, mobil sync, real-time analytics) va qachon emas (ko'p jadvalli murakkab tranzaksiyali buxgalteriya, ad-hoc relational hisobot), tarix (10gen, 2009, MMAPv1 dan WiredTiger'ga, 4.0 multi-document transaction, 5.0 time series, 6.0 Queryable Encryption preview, 7.0, 8.0 unumdorlik), litsenziya (SSPL va nima uchun bu "open source" emas deb hisoblanadi), Community vs Enterprise vs Atlas, FerretDB va DocumentDB (Amazon) mosligi va farqi
2. **BSON va tiplar**: JSON vs BSON (binar, tipli, uzunlik prefiksi, traversal tezligi), tiplar: `ObjectId` (12 bayt: timestamp, random, counter; `getTimestamp()`; nima uchun monotonik o'suvchi va shard key uchun xavfli), `String` (UTF-8), `Int32`/`Int64` (`NumberInt`, `NumberLong`) va `Double` farqi (JS'da hamma son `double` tuzog'i), `Decimal128` (`NumberDecimal`, pul uchun majburiy), `Date` (UTC millisekund) va `Timestamp` (ichki, oplog uchun) farqi, `Binary`/`UUID` (subtype 4), `Boolean`, `Null` va maydon yo'qligi farqi, `Array`, embedded document, `MinKey`/`MaxKey`, `Regex`, Extended JSON (canonical vs relaxed, `EJSON.stringify`), tiplar bo'yicha saralash tartibi (BSON comparison order), `$type` operatori, 16 MB hujjat chegarasi va 100 darajali nesting chegarasi, maydon nomlari qoidalari (`$` va `.`), maydon tartibi saqlanishi
3. **Arxitektura va WiredTiger**: `mongod` jarayoni, storage engine qatlami, WiredTiger: B-tree (hujjat va indeks uchun alohida jadval), document-level concurrency (optimistic, write conflict va retry), MVCC va snapshot, cache (default RAM'ning 50% minus 1 GB, dirty va clean sahifalar, eviction threadlari), checkpoint (har 60 soniya, barqaror nuqta), journal (write-ahead log, `j: true`, 100 ms commit interval), compression (snappy default, zstd, zlib; indeks uchun prefix compression), fayl tuzilishi (`collection-*.wt`, `index-*.wt`, `WiredTiger.wt`, `_mdb_catalog`), `db.serverStatus().wiredTiger`, `storageEngine` sozlamalari, in-memory engine (Enterprise), relational DB'ning buffer pool va WAL bilan solishtirish (`theory/` havola)
4. **mongosh va asboblar**: `mongosh` JS REPL (Node.js asosida, `async`/`await` ishlaydi, `load()` bilan skript), `use`, `show dbs/collections`, `db.getSiblingDB`, `db.runCommand` va admin buyruqlari, `printjson`/`EJSON`, `.mongoshrc.js`, `--eval`, `--file`, `--quiet`, `config.set`, MongoDB Compass (vizual explain, schema analysis), Database Tools (`mongoimport`/`mongoexport`, `mongodump`/`mongorestore`, `bsondump`, `mongostat`, `mongotop`), connection string (`mongodb://` vs `mongodb+srv://`, `replicaSet`, `authSource`, `retryWrites`, `w`, `readPreference`), docker'dagi bitta node'li replica set nima uchun kerak (transaction, change stream)

## II bosqich: CRUD va so'rovlar
5. **Insert va find**: `insertOne`/`insertMany` (`ordered: false` va qisman muvaffaqiyat), `_id` avtomatik generatsiyasi va o'z `_id` ingizni berish, `find`/`findOne`, cursor (batch, `getMore`, 10 daqiqa idle timeout, `noCursorTimeout` xavfi), `sort`/`skip`/`limit` va skip pagination'ning narxi (keyset pagination bilan almashtirish), `countDocuments` vs `estimatedDocumentCount` vs eskirgan `count`, `distinct`, `cursor.toArray()` xotira tuzog'i, iteratsiya (`forEach`, `for await`), SQL'dagi `SELECT ... WHERE ... ORDER BY ... LIMIT` bilan bir-biriga xaritalash
6. **Query operatorlari**: comparison (`$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`), logical (`$and` implicit va explicit, `$or`, `$nor`, `$not`), element (`$exists`, `$type`), maydon yo'q vs `null` (`{x: null}` ikkalasini topadi), dot notation bilan embedded va massiv ichiga kirish, array operatorlari (`$all`, `$size`, `$elemMatch` va nima uchun `{"a.b": 1, "a.c": 2}` boshqa elementlarga mos keladi), evaluation (`$expr` bilan maydonlarni solishtirish va aggregation ifodalari, `$regex` va anchored prefix indeks ishlatishi, `$mod`, `$jsonSchema` so'rovda, `$text`, eskirgan `$where` va nima uchun ishlatmaslik), bitwise (`$bitsAllSet`), geospatial (`$near`, `$geoWithin`, `$geoIntersects`), collation bilan katta-kichik harfga sezgir bo'lmagan so'rov, NoSQL injection (`{ $gt: "" }` foydalanuvchi kiritmasidan, `sanitize`)
7. **Projection va natija shakli**: inclusion vs exclusion (aralashtirib bo'lmaydi, `_id` istisno), embedded maydon projection, array projection (`$slice`, `$elemMatch`, positional `$`), projection'da aggregation ifodalari (4.4+), covered query uchun projection ahamiyati, tarmoq trafigini kamaytirish, SQL `SELECT *` antipattern'ining ekvivalenti
8. **Update operatorlari**: `updateOne`/`updateMany`/`replaceOne` farqi, `findOneAndUpdate` (`returnDocument: "after"`, atomar "o'qib-yangila"), field operatorlar (`$set`, `$unset`, `$inc`, `$mul`, `$min`, `$max`, `$rename`, `$currentDate`, `$setOnInsert`), array operatorlar (`$push` va `$each`/`$slice`/`$sort`/`$position` modifikatorlari, `$addToSet`, `$pop`, `$pull`, `$pullAll`), positional `$` (birinchi mos element), all-positional `$[]`, filtered positional `$[<id>]` va `arrayFilters`, upsert (`upsert: true`, filter'dagi qiymatlar hujjatga qo'shilishi, unique indekssiz parallel upsert'da dublikat tuzog'i), update pipeline (4.2+: `[{ $set: ... }]` bilan maydondan maydonga hisoblash, `$$NOW`), atomarlik: bitta hujjat ichida hamma narsa atomar, counter va inventory misollari
9. **Delete, bulkWrite va yozish semantikasi**: `deleteOne`/`deleteMany`, `findOneAndDelete`, `drop` vs `deleteMany({})` (indekslar va narx), soft delete patterni, `bulkWrite` (ordered vs unordered, aralash insert/update/delete, xato hisobotini o'qish), 8.0 dagi klaster darajasidagi `bulkWrite` buyrug'i (bir nechta collection), write concern (`w: 0/1/"majority"`, `j`, `wtimeout`) va har birining kafolati, read concern (`local`, `available`, `majority`, `linearizable`, `snapshot`), read preference (`primary`, `primaryPreferred`, `secondary`, `secondaryPreferred`, `nearest`, `maxStalenessSeconds`, tag set), causal consistency session, "o'z yozganingni o'qi" kafolati qachon buziladi, retryable writes va idempotentlik

## III bosqich: Data modeling
10. **Embed vs reference**: modellashtirish jarayoni (workload: so'rovlar va chastotasi birinchi, keyin entity, keyin pattern), munosabat turlari va qaror: one-to-one, one-to-few (embed), one-to-many (embed yoki child reference), one-to-squillions (parent reference), many-to-many (ikki tomonlama reference massivi), embed qilish mezonlari (birga o'qiladi, birga o'zgaradi, chegaralangan o'sish), reference mezonlari (mustaqil hayot sikli, katta yoki cheksiz o'sish, ko'p joydan murojaat), denormalizatsiya va ma'lumot dublikatsiyasi narxi (yangilash anomaliyasi, eventual consistency), relational sxemani MongoDB'ga ko'chirishda "jadval = collection" xatosi
11. **Schema design patternlari I**: attribute pattern (o'zgaruvchan atributlar `[{k, v}]` va bitta indeks), bucket pattern (IoT va time series, hujjatda N ta o'lchov, time series collection'dan oldingi usul), computed pattern (oldindan hisoblangan agregatlar, yozishda hisoblash), subset pattern (eng so'nggi N ta element embed, qolgani alohida), extended reference (tez-tez kerak bo'lgan maydonlar nusxasi), outlier pattern (juda katta hujjatlar uchun overflow va `has_extras` bayrog'i), har biri uchun qachon va qachon emas
12. **Schema design patternlari II**: polymorphic pattern (bir collection'da turli shakl, `type` maydoni), schema versioning (`schema_version`, lazy migration, ilova ikki versiyani o'qiydi), tree patternlari (parent reference, child reference, array of ancestors, materialized path, nested sets: har birining o'qish va yozish narxi), approximation pattern (har N-chi yozuvda hisoblagich), archive pattern (eski ma'lumotni boshqa collection yoki Online Archive'ga), document versioning (tarix), pre-allocation, anti-patternlar: unbounded arrays, juda ko'p collection (har birida indeks va fayl), keraksiz indekslar, katta hujjatlar va 16 MB chegaraga yaqinlashish, `$lookup` ga ortiqcha tayanish, case-insensitive so'rov collation'siz
13. **Schema validation va sxema boshqaruvi**: `$jsonSchema` validator (`bsonType`, `required`, `properties`, `enum`, `minimum`, `pattern`, `additionalProperties`, `oneOf`), query operatorli validator, `validationLevel` (`strict`, `moderate`, `off`), `validationAction` (`error`, `warn`, 7.1+ `errorAndLog`), mavjud collection'ga `collMod` bilan validator qo'shish, validatsiya xato tafsilotlari (5.0+), ilova tomonida sxema (Mongoose, Zod, Pydantic) vs DB tomonida, migratsiya strategiyalari (eager vs lazy, `migrate-mongo`), sxema tahlili (Compass schema tab, `$sample` bilan)

## IV bosqich: Indekslar va unumdorlik
14. **Indeks turlari**: single field, compound va maydon tartibi, ESR qoidasi (Equality, Sort, Range) va nima uchun ishlaydi, prefix qoidasi, multikey (massiv elementlari, ikkita massiv maydonli compound cheklovi), text indeks (bitta collection'ga bitta, til, weights, `$text` va `$meta: "textScore"`, Atlas Search bilan farqi), 2dsphere (GeoJSON), hashed (sharding uchun), wildcard (`$**`, attribute pattern o'rniga), unique (va `null`/yo'q maydon bilan muammo), partial (`partialFilterExpression`, sparse'dan afzal), sparse, TTL (`expireAfterSeconds`, TTL monitor har 60 soniya, aniqlik kafolati yo'q), hidden indeks (o'chirishdan oldin sinash), collation'li indeks, clustered collection (5.3+), indeks yaratish (rolling build, 4.2+ optimallashtirilgan build), `db.collection.getIndexes`, `$indexStats` bilan ishlatilmagan indeksni topish, har indeksning yozish narxi va RAM'dagi joyi
15. **explain va query planner**: `explain("queryPlanner" | "executionStats" | "allPlansExecution")`, stage'lar (`COLLSCAN`, `IXSCAN`, `FETCH`, `SORT` xotirada va 100 MB chegara, `SORT_MERGE`, `PROJECTION_COVERED`, `SHARD_MERGE`), asosiy metrikalar: `nReturned`, `totalKeysExamined`, `totalDocsExamined` va ideal nisbat 1:1:1, covered query, query planner (kandidat rejalar poygasi, trial period, plan cache, query shape va `planCacheKey`, cache invalidatsiyasi), `hint()` qachon va xavfi, `planCacheClear`, 8.0 dagi query settings (`setQuerySettings`) bilan rejani majburlash, slot-based execution engine (SBE) qisqacha
16. **Unumdorlik va working set**: working set (tez-tez ishlatiladigan hujjat va indekslar) RAM'ga sig'ishi kerak, WiredTiger cache'ni kuzatish (`bytes currently in the cache`, dirty ratio, eviction), indeks hajmi (`totalIndexSize`), hujjat o'lchami va keraksiz maydonlar, yozish yuklamasi (write conflict, journal, checkpoint), connection pool sozlash (`maxPoolSize`, `minPoolSize`, `maxIdleTimeMS`), batch o'lchami, `$in` ro'yxati uzunligi, regex va `$ne`/`$nin` indeksdan foydalanmasligi, keyset pagination, katta skan uchun secondary'dan o'qish va uning tuzoqlari, `mongostat`/`mongotop` bilan bottleneck topish
17. **Profiler va diagnostika**: database profiler (`db.setProfilingLevel(1, { slowms: 100 })`, `system.profile` collection'i va tahlili), slow query log (`mongod.log`, JSON format, `COMMAND` komponenti), `db.currentOp()` va `db.killOp()`, `$currentOp` aggregation, `serverStatus` metrikalari (opcounters, connections, globalLock, wiredTiger), FTDC (full time diagnostic data capture) nima, Atlas Performance Advisor va Query Profiler, indeks tavsiyalarini qanday baholash, real holat: sekin endpoint'dan sekin so'rovgacha

## V bosqich: Aggregation va server-side logika
18. **Aggregation pipeline asoslari**: pipeline modeli (stage'lar ketma-ketligi, Unix pipe analogi), `$match`, `$project`, `$addFields`/`$set`, `$unset`, `$group` (`_id` bilan guruhlash, `$sum`, `$avg`, `$min`, `$max`, `$first`, `$last`, `$push`, `$addToSet`, `$count`, 5.2+ `$top`/`$bottom`/`$topN`/`$firstN`), `$sort`, `$limit`, `$skip`, `$count`, `$sortByCount`, `$replaceRoot`/`$replaceWith`, `$sample`, SQL `GROUP BY`/`HAVING` bilan xarita (`$group` dan keyin `$match`), aggregation natijasini o'qish va debug qilish (bosqichma-bosqich qurish, Compass aggregation builder), cursor sifatida qaytishi
19. **Join va massivlar**: `$lookup` (oddiy equality, `let`/`pipeline` bilan korrelyatsiyalangan sub-pipeline, 5.0+ qisqa sintaksis), `$lookup` unumdorligi (foreign collection'da indeks shart, sharded collection cheklovlari va 5.1+ yengillashtirish), `$graphLookup` (rekursiv qidiruv: org chart, ijtimoiy graf, `maxDepth`, `depthField`, `restrictSearchWithMatch`), `$unwind` (`preserveNullAndEmptyArrays`, `includeArrayIndex`, unwind'dan keyin group'ning narxi), `$unionWith` (SQL `UNION ALL`), qachon `$lookup` modeldagi xato belgisi
20. **Murakkab stage'lar**: `$facet` (bitta o'qishda bir nechta natija: qidiruv natijasi va filtr hisoblagichlari), `$bucket` va `$bucketAuto` (gistogramma), `$setWindowFields` (5.0+: `partitionBy`, `sortBy`, `output`, `window: { documents: [...] }` va `range`, `$rank`, `$denseRank`, `$documentNumber`, `$shift`, `$derivative`, `$integral`, harakatlanuvchi o'rtacha, kumulyativ yig'indi, SQL window function bilan solishtirish), `$densify` va `$fill` (bo'sh vaqt oraliqlarini to'ldirish, `locf`, `linear`), `$merge` (`whenMatched`/`whenNotMatched`, on-demand materialized view, incremental yangilash) va `$out` (to'liq almashtirish) farqi, `$redact`, `$geoNear`
21. **Expression operatorlari**: arifmetik (`$add`, `$subtract`, `$multiply`, `$divide`, `$round`, `$trunc`, `$mod`), string (`$concat`, `$substrCP` vs `$substrBytes`, `$toUpper`, `$split`, `$trim`, `$regexMatch`/`$regexFind`/`$regexFindAll`, `$replaceAll`), date (`$dateToString`, `$dateFromString`, `$dateTrunc`, `$dateAdd`, `$dateDiff`, timezone argumenti va UTC tuzog'i), conditional (`$cond`, `$ifNull`, `$switch`), tip konvertatsiya (`$convert` va `onError`, `$toInt`, `$toDecimal`, `$toObjectId`), massiv (`$map`, `$filter`, `$reduce`, `$arrayElemAt`, `$slice`, `$zip`, `$size`, `$in`, `$sortArray` 5.2+, `$arrayToObject`/`$objectToArray`), set (`$setUnion`, `$setIntersection`), obyekt (`$mergeObjects`, `$getField`/`$setField`), o'zgaruvchilar (`$let`, `$$ROOT`, `$$CURRENT`, `$$NOW`, `$$REMOVE`), bu operatorlar `find` (`$expr`), update pipeline va validator'da ham ishlashi: "MongoDB'ning funksiya tili"
22. **Pipeline optimizatsiyasi**: avtomatik optimizatsiyalar (`$match` va `$sort` ni oldinga surish, `$sort` + `$limit` birlashuvi, `$project` olib tashlash), `$match` va `$sort` boshida bo'lsa indeks ishlatilishi, `explain` bilan aggregation tahlili, 100 MB stage xotira chegarasi va `allowDiskUse` (6.0+ default `allowDiskUseByDefault`), `$group` va `$sort` spill, `$lookup` N+1 narxi, sharded klasterda pipeline bo'linishi (shard qismi va merger qismi), `$merge` bilan oldindan hisoblash vs har so'rovda hisoblash, aggregation vs ilova kodida hisoblash qarori
23. **Server-side JavaScript va "procedura" ekvivalentlari**: MongoDB'da stored procedure yo'qligi va nima uchun, tarix: `db.eval` (o'chirilgan), `system.js` stored JavaScript (eskirgan), `$where` (eskirgan), `mapReduce` (5.0 dan eskirgan, aggregation'ga migratsiya), hozirgi vositalar: `$function` (JS funksiyani aggregation ichida, `body`, `args`, `lang: "js"`), `$accumulator` (custom `init`/`accumulate`/`merge`/`finalize` bilan custom agregat), ularning narxi (JS engine, indeks yo'q, sharded merge, `security.javascriptEnabled`, Atlas'da cheklov, 8.0 da server-side JS eskirish e'loni bo'lsa uni tekshirish), ko'p qadamli biznes logika qayerda turishi kerak: ilova servisi + transaction, aggregation ifodalari bilan "deklarativ funksiya", Atlas Functions va Atlas Triggers (database, scheduled, authentication trigger; serverless JS, `context.services`), relational stored procedure'ni MongoDB'ga ko'chirish strategiyasi
24. **Views va materialized views**: standard view (`db.createView`, aggregation pipeline ustida, faqat o'qish, indeks base collection'dan), view cheklovlari (`$out`/`$merge` yo'q, find projection cheklovlari), on-demand materialized view (`$merge` bilan, cron/Atlas scheduled trigger bilan yangilash, incremental yangilash `$match` sana bo'yicha), materialized view'ga indeks qo'shish, relational `CREATE MATERIALIZED VIEW` va `REFRESH` bilan solishtirish, CQRS read model sifatida

## VI bosqich: Tranzaksiya, oqim va maxsus collection'lar
25. **Transactions**: bitta hujjat atomarligi (ko'p hollarda yetarli: model to'g'ri bo'lsa), multi-document transaction (4.0 replica set, 4.2 sharded), session (`startSession`, `withTransaction` callback API va avtomatik retry, `TransientTransactionError` va `UnknownTransactionCommitResult` label'lari), snapshot isolation va write conflict, `readConcern: "snapshot"`, `writeConcern: "majority"`, cheklovlar (60 soniya `transactionLifetimeLimitSeconds`, oplog entry hajmi, DDL cheklovlari), narxi (lock, cache bosimi, sharded'da 2PC), retryable writes va retryable reads, "transaction ishlatishdan oldin modelni qayta ko'r" qoidasi, pul o'tkazish va inventar zaxira misollari, relational izolyatsiya darajalari bilan solishtirish (`theory/` havola)
26. **Change streams**: `watch()` (collection, database, deployment darajasida), oplog asosida ishlashi va replica set talabi, event turlari (`insert`, `update` va `updateDescription`, `replace`, `delete`, `invalidate`, DDL eventlari 6.0+ `showExpandedEvents`), pipeline bilan filtrlash, `fullDocument: "updateLookup"` va uning race'i, pre- va post-image'lar (6.0+, `changeStreamPreAndPostImages`), resume token (`resumeAfter`, `startAfter`, `startAtOperationTime`) va oplog window'dan chiqib ketish, at-least-once va idempotent iste'molchi, ishlatilishi: cache invalidatsiyasi, outbox, search index sync, CDC (Debezium MongoDB connector, `data-engineering/` havola), relational trigger o'rnini bosishi
27. **Time series collections**: `timeseries: { timeField, metaField, granularity }` (5.0+), ichki bucket saqlash (ustunli siqish), `bucketMaxSpanSeconds`/`bucketRoundingSeconds` (6.3+), metaField bo'yicha indeks va secondary indekslar, `expireAfterSeconds`, cheklovlar (update/delete imkoniyatlari versiyalar bo'yicha kengaygan), window function va `$densify` bilan tahlil, bucket pattern bilan solishtirish, TimescaleDB/InfluxDB/ClickHouse bilan qachon qaysi (`timeseries/` havola)
28. **Capped collection, GridFS va clustered collection**: capped collection (qat'iy o'lcham, insertion tartib, FIFO, tailable cursor, log va queue uchun, cheklovlar, TTL va time series bilan almashtirish), GridFS (16 MB dan katta fayllar, `fs.files` va `fs.chunks`, 255 KB chunk, `GridFSBucket` driverda, qachon S3 yaxshiroq), clustered collection (`clusteredIndex`, `_id` bo'yicha tartiblangan saqlash, TTL bilan), collation va til bo'yicha saralash

## VII bosqich: Replica set va sharding
29. **Replica set**: primary, secondary, arbiter (va nima uchun arbiter tavsiya etilmaydi), saylov (Raft asosidagi protokol `pv1`, heartbeat, `electionTimeoutMillis`, priority, votes, hidden va delayed member), oplog (idempotent operatsiyalar, `oplogSizeMB`, oplog window, `rs.printReplicationInfo`), replikatsiya lag, rollback (majority'ga yozilmagan yozuvlar va `rollback/` fayllar, `w: "majority"` uni oldini olishi), `rs.initiate`, `rs.add`, `rs.status`, `rs.stepDown`, failover'ni docker'da sinash (konteynerni to'xtatish), driverning failover'ga reaksiyasi va retryable writes, read preference va eventual consistency tuzoqlari, `theory/` dagi leader-based replication bilan bog'lash
30. **Sharding arxitekturasi**: nima uchun va qachon (yozish yuklamasi yoki hajm bitta replica set'dan oshganda, oldin vertikal va indeks), komponentlar: `mongos` router, config server replica set, shard'lar (har biri replica set), chunk (range, 7.0+ default 128 MB), balancer va chunk migratsiyasi, targeted vs scatter-gather (broadcast) so'rov, sharded collection'da unique indeks cheklovi, `sh.status()`, `sh.shardCollection`, docker'da 2 shard'li klaster
31. **Shard key va masshtablash strategiyasi**: shard key tanlash mezonlari (yuqori kardinallik, past chastota, monotonik emas, so'rovlarda ishtirok), ranged vs hashed sharding (yozish taqsimoti vs range so'rov), compound shard key, jumbo chunk, hot shard, monotonik `ObjectId`/timestamp tuzog'i, zone sharding (geografik joylashuv, ma'lumot rezidentligi), resharding (5.0+ `reshardCollection`, narxi), 6.0+ refineCollectionShardKey, 8.0 dagi sharding yaxshilanishlari (unshardCollection, moveCollection) faqat versiya ko'rsatib, shard key xatosini production'da tuzatish narxi, Cassandra va DynamoDB partition key bilan solishtirish

## VIII bosqich: Ekspluatatsiya va ekotizim
32. **Security**: autentifikatsiya (SCRAM-SHA-256, x.509, LDAP va Kerberos Enterprise'da, OIDC), `--auth` va localhost exception, RBAC (built-in rollar: `read`, `readWrite`, `dbAdmin`, `userAdmin`, `clusterAdmin`, `root`; custom rol va privilege, least privilege), TLS/SSL, network binding (`bindIp`, ochiq MongoDB'lar va ransomware tarixi), auditing (Enterprise/Atlas), encryption at rest, Client-Side Field Level Encryption (CSFLE: deterministic vs random, key vault, KMS), Queryable Encryption (equality 7.0 GA, range 8.0 GA: shifrlangan maydonda so'rov), NoSQL injection va operator injection, `$where`/`$function` va JS'ni o'chirish (`javascriptEnabled: false`)
33. **Backup va tiklash**: `mongodump`/`mongorestore` (logical, `--oplog` bilan izchil nusxa, katta DB uchun sekinligi), filesystem snapshot (LVM, EBS, journal bilan izchillik, `fsyncLock`), point-in-time recovery (oplog asosida), Ops Manager/Cloud Manager va Atlas backup, Percona Backup for MongoDB, tiklashni muntazam sinash, `mongoexport` backup emasligi (tip yo'qotishi), RPO/RTO va DR rejasi
34. **Monitoring va upgrade**: asosiy metrikalar (opcounters, latency, replication lag, cache, connections, queue, page faults, oplog window), `mongostat`, `mongotop`, `db.serverStatus`, `rs.status`, Prometheus `mongodb_exporter` va Grafana, alerting chegaralari, log tahlili (JSON log, `jq` bilan), rolling upgrade (secondary'lar, keyin stepDown), Feature Compatibility Version (`setFeatureCompatibilityVersion`), Atlas vs self-hosted qarori, Kubernetes operatorlari (MongoDB Community/Enterprise Operator, Percona Operator)
35. **Driverlar, ODM va Atlas ekotizimi**: rasmiy driverlar (Node.js `mongodb`, Go `mongo-go-driver` v2, Python `pymongo` va async `AsyncMongoClient`), `MongoClient` ni bitta marta yaratish va pool, `ObjectId`/`Decimal128` ning JS/Go/Python'dagi ifodasi, Mongoose (schema, middleware, `populate` = yashirin N+1, `lean()`, `strict`, validatsiya DB'da emasligi), Prisma va boshqa ORM'lar MongoDB bilan cheklovlari, Atlas Search (Lucene asosida, `$search` stage, analyzer, faceting, autocomplete; `elasticsearch/` bilan solishtirish), Atlas Vector Search (`$vectorSearch`, kirish; chuqur: `vector/`), Atlas Data Federation va Online Archive, Atlas Device Sync tarixi (eskirgan), `mongodb-atlas-local` docker image bilan lokal sinov

## IX bosqich: Loyihalar
36. **Loyiha 1: e-commerce katalog va buyurtma servisi**: polymorphic katalog (attribute pattern, wildcard indeks), buyurtma (extended reference, subset pattern sharhlar uchun), inventar zaxira transaction bilan va bitta hujjat atomar variant bilan solishtirish, `$facet` bilan qidiruv filtrlari, `$setWindowFields` bilan sotuv analitikasi, `$merge` bilan kunlik materialized hisobot, `$jsonSchema` validatsiya, har so'rov uchun `explain` hisobotida 1:1:1 nisbat, `test.js` testlari, README'da modellashtirish qarorlari
37. **Loyiha 2: event va IoT platforma**: time series collection'ga yozish generatori, change stream iste'molchisi (resume token saqlash, idempotent qayta ishlash, pre/post image), real-time agregat (`$merge` incremental), TTL bilan retention, docker'da replica set failover paytida ma'lumot yo'qotmaslikni isbotlash (`w: "majority"`, retryable writes), ixtiyoriy: shard key tanlab 2 shard'li klasterga o'tkazish va taqsimotni `sh.status()` bilan ko'rsatish
38. **Kod sharhi va migratsiya mashqi**: PostgreSQL'dagi kichik relational sxemani (5–6 jadval, stored procedure va trigger bilan) MongoDB'ga ko'chirish: workload tahlili, model qarori hujjati, stored procedure'larni aggregation/ilova kodi/transaction'ga, trigger'larni change stream'ga almashtirish, ikki tizimda bir xil hisobot natijasini tekshirish
