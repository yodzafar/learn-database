# Graph DB rejasi: Neo4j, Cypher, GQL va graph algoritmlari

Nima uchun alohida: ba'zi savollar munosabatlarning o'zi haqida: "do'stimning do'stlari nima sotib olgan", "bu tranzaksiya zanjiri firibgarlik halqasini hosil qiladimi", "A dan B gacha eng qisqa yo'l", "bu xizmat ishdan chiqsa qaysi xizmatlar zarar ko'radi". Relational bazada bunday savol har qadamda yana bitta `JOIN` (yoki rekursiv CTE) degani, chuqurlik oshgani sari so'rov ham, xarajat ham portlaydi. Graph DB munosabatni birinchi darajali obyekt sifatida saqlaydi va traversal'ni chuqurlikka emas, tegilgan qism hajmiga proporsional qiladi. Recommendation, fraud detection, knowledge graph, identity/access graph, network/IT topology, supply chain va GraphRAG (LLM uchun bilim grafi) asosiy qo'llanish joylari.

Asosiy engine Neo4j 5 (Community Edition, Cypher). Standart: 2024-yilda ISO/IEC 39075 GQL (Graph Query Language) qabul qilindi, SQL dan keyingi birinchi yangi ISO so'rov tili; Cypher unga eng yaqin va Neo4j uni bosqichma-bosqich GQL ga moslashtirmoqda. Taqqoslash uchun Apache AGE (Postgres ichida openCypher), Memgraph, Amazon Neptune, ArangoDB.

Boshlash: `sql/` I–II bosqich (JOIN, rekursiv CTE: graph savolini avval SQL da yozib, keyin Cypher bilan solishtiramiz), `theory/` dagi data modeling. Graf nazariyasi (vertex, edge, yo'nalish, BFS/DFS, Dijkstra) ../learn-golang yoki ../learn-python `dsa/` dagi graf mavzularidan tanish bo'lsa yaxshi.

Ishlash tartibi: `graph/docs/NN-nom.md` nazariya va vazifalar, kod `graph/NN-slug/main.cypher` (`cypher-shell -f` bilan bajariladi, har vazifa `// N. Title` komment bilan boshlanadi), seed ma'lumot `seed.cypher` yoki `data/*.csv` (`LOAD CSV`), tekshiruv `test.cypher` (kutilgan natija bilan solishtiradigan so'rovlar, `make graph-test` qator sonini va qiymatni tekshiradi). Konteyner `ldb-neo4j` (Neo4j 5 Community, APOC va GDS pluginlari compose orqali yoqilgan, GDS 13-mavzuda ishlatiladi), Neo4j Browser `http://localhost:7474`. Buyruqlar: `make up db=neo4j`, `make shell db=neo4j`, `make graph n=01`, `make graph-test n=01`, `make reset db=neo4j`.

## Boshqa DBlar bilan solishtirish

| Mavzu | PostgreSQL | MongoDB | Neo4j |
|---|---|---|---|
| Munosabat | foreign key + `JOIN` (so'rov vaqtida) | embed yoki `$lookup`/`$graphLookup` | relationship saqlanadi, pointer orqali |
| Chuqur traversal | rekursiv CTE, chuqurlik oshgani sari qimmat | `$graphLookup`, cheklangan | asosiy vazifa, variable-length path |
| Sxema | qat'iy | ixtiyoriy | ixtiyoriy (label, property), constraints bilan |
| So'rov tili | SQL | MQL | Cypher, GQL (ISO 39075) |
| Procedura | PL/pgSQL | `$function` | APOC, Java user-defined procedures/functions |
| Tranzaksiya | ACID | ACID | ACID |
| Masshtablash | replika, sharding (Citus) | sharding | read replika va cluster; sharding cheklangan (Fabric/composite DB) |
| Kuchli joyi | umumiy OLTP | hujjat | ko'p-hop munosabat so'rovlari |

## I bosqich: Graph model va Neo4j

1. **Graph model va qachon graph DB**: property graph (node, relationship, label, relationship type, property) vs RDF (triple: subject-predicate-object, IRI, ontologiya), yo'naltirilgan va yo'naltirilmagan munosabat, graph DB qachon to'g'ri tanlov (munosabatlar ko'p-hop, sxema o'zgaruvchan, "path" savollari) va qachon noto'g'ri (oddiy CRUD, katta aggregatsiya va hisobot, bulk analytics), native graph DB vs graph layer (Postgres AGE, SQL/PGQ: SQL:2023 property graph queries), "friends of friends" savolini Postgres'da rekursiv CTE bilan yozish va 2/3/4 chuqurlikda vaqtini o'lchash (keyin Cypher bilan solishtiriladi), graph DB bozori (Neo4j, Memgraph, Neptune, ArangoDB, TigerGraph, JanusGraph, NebulaGraph) va GraphRAG trendi
2. **Neo4j arxitekturasi**: native graph storage (node store, relationship store, property store, fixed-size record'lar, record id bo'yicha O(1) murojaat), index-free adjacency (har node o'z munosabatlariga to'g'ridan-to'g'ri ko'rsatkichga ega, traversal indexga bog'liq emas) va uning chegaralari (supernode, "dense node"), 5.x da yangi `block` storage format (Enterprise, versiyani tekshirish), page cache va heap (`server.memory.pagecache.size`, `server.memory.heap.max_size`), transaction log, Community vs Enterprise farqlari (cluster, role-based security, online backup, multi-database), database'lar (`system`, `neo4j`, `CREATE DATABASE` Enterprise'da), Bolt protokoli va driverlar, Neo4j Browser, `cypher-shell`, Neo4j Desktop/Aura (cloud), konteynerda ishga tushirish (`NEO4J_AUTH`, `NEO4J_PLUGINS='["apoc"]'`, volume'lar)
3. **Graph data modeling**: domen savollaridan model chiqarish (query-driven modeling, "whiteboard friendly"), node vs relationship vs property qarori, label dizayni (ko'p label, `:Person:Employee`), relationship type nomlash (`:PURCHASED`, fe'l, UPPER_SNAKE), relationship property qachon (vaqt, og'irlik, miqdor) va qachon intermediate node kerak (hyperedge: `(:Person)-[:PLACED]->(:Order)-[:CONTAINS]->(:Product)`), vaqt modellari (time tree, linked list `:NEXT`, timestamp property), supernode muammosi va yechimlari (fan-out bo'lish, relationship type bo'yicha ajratish), relational sxemani grafga o'girish (FK → relationship, join table → relationship + property), anti-patternlar (hamma narsani property qilish, umumiy `:RELATED_TO`), Arrows.app bilan model chizish

## II bosqich: Cypher chuqur

4. **Cypher asoslari: CREATE, MATCH, WHERE, RETURN**: pattern sintaksisi (`(n:Label {prop: value})-[r:TYPE]->(m)`), `CREATE`, `MATCH` va `WHERE` (taqqoslash, `IN`, `STARTS WITH`/`ENDS WITH`/`CONTAINS`, `=~` regex, `IS NULL`, pattern predicate `WHERE (a)-->(b)`, `EXISTS {}` subquery), `RETURN` (`DISTINCT`, alias, `ORDER BY`, `SKIP`/`LIMIT`), tiplar (Integer, Float, String, Boolean, List, Map, temporal: `date()`, `datetime()`, `duration()`, spatial: `point()`), `NULL` semantikasi (yo'q property = `null`, uch qiymatli mantiq SQL dagidek), parametrlar (`$name`, `:param` cypher-shell'da) va nega literal o'rniga parametr (query plan keshi, injection), `EXPLAIN` bilan birinchi tanishuv, movie dataset (`:play movies`) ustida mashq
5. **Ma'lumotni o'zgartirish: MERGE, SET, REMOVE, DELETE**: `MERGE` semantikasi (butun pattern bo'yicha "bor bo'lsa top, bo'lmasa yarat") va eng ko'p xato (`MERGE (a)-[:R]->(b)` da a va b ham yaratilib ketishi, to'g'ri usul: avval node'larni alohida `MERGE`, keyin relationship), `ON CREATE SET`/`ON MATCH SET`, `MERGE` va unique constraint (race condition, nega constraint shart), `SET` (property, `+=` map bilan, label qo'shish), `REMOVE`, `DELETE` vs `DETACH DELETE`, katta o'chirish (`CALL { ... } IN TRANSACTIONS OF 10000 ROWS`), idempotent seed skriptlar yozish, `FOREACH` qisqa, tranzaksiya chegarasi cypher-shell'da (`:begin`/`:commit`)
6. **Path so'rovlari**: variable-length relationship (`-[:KNOWS*1..3]->`, chegarasiz `*` xavfi), path o'zgaruvchisi (`p = (a)-[*]->(b)`, `nodes(p)`, `relationships(p)`, `length(p)`), `shortestPath()` va `allShortestPaths()`, Neo4j 5 quantified path patterns (`((a)-[:R]->(b)){1,5}`, inline `WHERE` bilan, guruh o'zgaruvchilar), GQL uslubidagi `SHORTEST k`/`ANY SHORTEST`/`ALL SHORTEST` (5.21+ atrofida, versiyani hujjatdan tekshirish), match mode va relationship uniqueness (bir path ichida relationship takrorlanmaydi), yo'nalishsiz pattern (`-[:R]-`) va natija ikki barobar tuzog'i, og'irlikli eng qisqa yo'l uchun GDS/APOC kerakligi, 1-mavzudagi SQL rekursiv CTE bilan solishtirish va vaqt o'lchash
7. **WITH, aggregatsiya va list'lar**: `WITH` (so'rovni bosqichlarga bo'lish, SQL dagi subquery/CTE ekvivalenti, keyingi qismga faqat o'tkazilganlar ko'rinadi), aggregatsiya implicit grouping (`RETURN n.city, count(*)`: aggregat bo'lmagan ustunlar grouping key, SQL `GROUP BY` siz), `count`, `sum`, `avg`, `min`/`max`, `collect` (va `collect(DISTINCT ...)`), `percentileCont`, `stDev`, `OPTIONAL MATCH` (SQL `LEFT JOIN` ekvivalenti, `null` bilan ishlash), `UNWIND` (list → qatorlar, batch yozish uchun `UNWIND $rows AS row MERGE ...`), list comprehension (`[x IN list WHERE ... | expr]`), pattern comprehension (`[(a)-->(b) | b.name]`), `reduce`, `CASE`, map projection (`n {.name, .age, friends: [...]}`: API uchun JSON shakllantirish), `UNION`/`UNION ALL`, top-N per group patterni
8. **Subquery va ma'lumot import**: `CALL { ... }` subquery (correlated, `WITH` import, 5.x da `CALL (x) { ... }` variable scope sintaksisi), `EXISTS {}`, `COUNT {}`, `COLLECT {}` subquerylar, `CALL { } IN TRANSACTIONS` (batch, `ON ERROR CONTINUE`/`BREAK`/`FAIL`, `REPORT STATUS`), `LOAD CSV WITH HEADERS FROM 'file:///...'` (tip konvertatsiyasi, `toInteger`, `date()`, `null` qiymatlar, `FIELDTERMINATOR`), import oldidan constraint yaratish nega shart (aks holda har `MERGE` full scan), eager operator tuzog'i va `PROFILE` da topish, katta import uchun `neo4j-admin database import full` (offline, CSV header formati `:ID`, `:LABEL`, `:START_ID`, `:END_ID`, `:TYPE`), Postgres'dan ma'lumotni grafga ko'chirish vazifasi (`COPY ... TO CSV` + `LOAD CSV`)

## III bosqich: Unumdorlik va kengaytirish

9. **Indekslar va constraints**: index turlari Neo4j 5 da (range, text, point, full-text (Lucene), token lookup, vector index 5.11+), `CREATE INDEX name IF NOT EXISTS FOR (n:Label) ON (n.prop)`, composite index, relationship property index, constraints (`IS UNIQUE`, `IS NODE KEY` va `IS NOT NULL` existence (Enterprise), property type constraint 5.9+ Enterprise; Community da qaysilari borligini tekshirish), `SHOW INDEXES`/`SHOW CONSTRAINTS`, index qachon ishlatiladi (faqat boshlang'ich nuqtani topish uchun, traversal'ga kerak emas: index-free adjacency), full-text qidiruv (`db.index.fulltext.queryNodes`, analyzer), index populating holati va `db.awaitIndexes()`
10. **Query tuning: EXPLAIN va PROFILE**: execution plan o'qish (pastdan yuqoriga), operatorlar (`AllNodesScan`, `NodeByLabelScan`, `NodeIndexSeek`, `Expand(All)`/`Expand(Into)`, `Filter`, `Eager`, `CartesianProduct`, `EagerAggregation`, `ProduceResults`), db hits va rows, cartesian product tuzog'i (bog'lanmagan pattern), eager operator (o'qish va yozishni ajratish, xotirani to'ldiradi, `CALL IN TRANSACTIONS` bilan yengish), planner hint'lari (`USING INDEX`, `USING SCAN`, `USING JOIN ON`), boshlang'ich nuqtani tanlash (anchor), supernode orqali traversal narxi, runtime'lar (slotted, pipelined (Enterprise), parallel 5.13+ Enterprise), query cache va parametrlar, `db.stats`/`SHOW TRANSACTIONS`/`TERMINATE TRANSACTION`, `query.log` (Enterprise) va slow query, sekin so'rovni bosqichma-bosqich tezlashtirish vazifasi
11. **APOC va procedura/funksiyalar**: `CALL procedure() YIELD ...` vs funksiya (ifoda ichida), `SHOW PROCEDURES`/`SHOW FUNCTIONS`, built-in `db.*`/`dbms.*`, APOC Core (5.x da APOC Core va APOC Extended ajratilgan): `apoc.periodic.iterate` (batch), `apoc.create.*` (dinamik label/type), `apoc.path.expandConfig`/`subgraphAll` (konfiguratsiyali traversal), `apoc.coll.*`, `apoc.map.*`, `apoc.text.*`, `apoc.date.*`, `apoc.load.json`/`jdbc` (Extended), `apoc.refactor.*` (node'larni birlashtirish), `apoc.meta.schema`, triggerlar (`apoc.trigger.install`, SQL trigger ekvivalenti, ehtiyot choralari), xavfsizlik (`dbms.security.procedures.unrestricted`/`allowlist`), APOC'siz Cypher 5 da qaysi ishlar endi bevosita qilinadi (`CALL IN TRANSACTIONS`, dinamik label 5.26+ `SET n:$(label)` atrofida, versiyani tekshirish)
12. **User-defined procedures va functions (Java)**: Neo4j procedura modeli (SQL stored procedure ekvivalenti, lekin Java'da va JVM ichida), `@Procedure` (`mode = READ/WRITE/SCHEMA`), `@UserFunction`, `@UserAggregationFunction`, `@Context GraphDatabaseService`/`Transaction`/`Log`, `Stream<Result>` qaytarish, Maven/Gradle loyiha (`neo4j` dependency `provided`), JAR ni `plugins/` ga qo'yish va konteynerni qayta ishga tushirish, `neo4j-harness` bilan unit test, traversal framework API (`TraversalDescription`) qachon Cypher'dan tezroq, xavfsizlik va versiya mosligi, vazifa: og'irlikli yo'l yoki maxsus scoring funksiyasini yozib Cypher'dan chaqirish (Java tanish bo'lmasa ../learn-golang/learn-python analogiyasi bilan qisqa kirish beriladi)

## IV bosqich: Algoritmlar va ekotizim

13. **Graph Data Science (GDS)**: GDS kutubxonasi (plugin, Community'da cheklangan parallellik), graph projection (`gds.graph.project`, native va Cypher projection, in-memory katalog), rejimlar (`stream`, `stats`, `mutate`, `write`), `estimate` bilan xotira hisoblash, centrality (PageRank, Betweenness, Degree, ArticleRank), community detection (Louvain, Leiden, Label Propagation, WCC: weakly connected components, Triangle Count), similarity (Node Similarity Jaccard, KNN), path finding (Dijkstra, A*, Yen's k-shortest, BFS/DFS, minimum spanning tree), node embeddings (FastRP, node2vec) va link prediction qisqa, natijani property sifatida yozib Cypher bilan ishlatish, har algoritm qaysi biznes savoliga javob berishi
14. **Tranzaksiyalar, cluster va ekspluatatsiya**: ACID va isolation (read committed, lock'lar: write lock node/relationship darajasida, deadlock va retry), driver'larda managed transaction (`executeRead`/`executeWrite`, avtomatik retry, idempotent bo'lishi shart), bookmark va causal consistency, cluster (5.x: primary/secondary server'lar, Raft, database topologiyasi; Enterprise), Fabric/composite databases (sharding o'rniga), backup (`neo4j-admin database dump`/`load` offline, online backup Enterprise), konfiguratsiya va memory sozlash (`neo4j-admin server memory-recommendation`), monitoring (metrics, `SHOW SERVERS`), security (userlar, role'lar Enterprise), upgrade yo'llari
15. **GQL, SQL/PGQ va RDF**: ISO/IEC 39075:2024 GQL (asosiy tushunchalar: graph type, `MATCH`, `INSERT`, `RETURN`, path mode'lar, Cypher bilan farqlar), SQL:2023 SQL/PGQ (Part 16: `GRAPH_TABLE`, relational jadvallar ustida property graph so'rovi; Oracle 23ai da bor, Postgres'da hali yo'q, versiyani tekshirish), RDF va SPARQL qisqa (triple store, `SELECT ?x WHERE { ?x :knows ?y }`, OWL, knowledge graph'lar: Wikidata so'rovi amaliyoti), property graph vs RDF tanlash, openCypher loyihasi
16. **Boshqa graph DBlar taqqosi**: Apache AGE (Postgres extension, `cypher()` funksiyasi SQL ichida, relational va graph ma'lumotni bitta bazada aralashtirish; konteynerda mashq), Memgraph (in-memory, Cypher mos, C++, streaming), Amazon Neptune (managed, Gremlin + openCypher + SPARQL, Neptune Analytics), ArangoDB (multi-model: hujjat + graph, AQL), TigerGraph (GSQL, MPP), JanusGraph va Gremlin/TinkerPop (traversal tili, `g.V().has('name','x').out('knows')`), NebulaGraph, qaror matritsasi (hajm, so'rov tili, operatsion xarajat, litsenziya), bitta savolni Cypher, AGE va Gremlin'da yozib solishtirish

## V bosqich: Loyiha

17. **Loyiha: recommendation va fraud detection**: (a) recommendation: foydalanuvchi, mahsulot, kategoriya, xarid grafi (Postgres'dagi e-commerce sxemasidan import), collaborative filtering Cypher bilan ("shu mahsulotni olganlar yana nimalar olgan"), GDS Node Similarity va PageRank bilan tavsiya, natijani API uchun map projection bilan qaytarish; (b) fraud detection: hisob, qurilma, IP, karta, tranzaksiya grafi, umumiy qurilma/IP orqali bog'langan halqalarni topish (WCC, Louvain), sikllar va qisqa yo'llar; ikkalasida constraint va indekslar, `PROFILE` bilan optimallashtirilgan so'rovlar, idempotent import, `test.cypher` bilan kutilgan natijalar, README'da nega bu masala uchun graph DB (va SQL rekursiv CTE bilan vaqt taqqosi)
