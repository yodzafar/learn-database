# SQL: standart SQL (ANSI/ISO) va dialektlar

Nima uchun alohida: SQL barcha relational DB'larning umumiy tili va eng uzoq yashaydigan texnik ko'nikma (1974 dan beri). Vendor modullari (`postgres`, `mysql`, `mssql`, `oracle`, `sqlite`) har bir DB'ning o'ziga xos qismini (arxitektura, procedural til, tuning, ekspluatatsiya) o'rgatadi; bu modul esa ularning hammasi uchun umumiy bo'lgan deklarativ SQL'ni standart (ISO/IEC 9075, SQL:2016 va SQL:2023) asosida chuqur o'rgatadi. Har mavzuda "standartda qanday" va "har bir vendorda qanday" jadvali bor, shuning uchun bu modul tugagach istalgan relational DB'da so'rov yozish faqat sintaksis farqiga aylanadi. Data engineering, backend va analytics intervyularining katta qismi aynan shu moduldagi mavzulardan (JOIN, window function, CTE, gaps-and-islands, top-N per group) iborat.

Boshlash: shart yo'q, bu loyihaning birinchi moduli. `../theory/docs/00-reja.md` I bosqichi (relational model va algebra) bilan parallel o'tish tavsiya etiladi. `make setup` (sqlfluff va boshqa asboblar) va `make up db=postgres` bir marta.

Ishlash tartibi: `sql/docs/NN-nom.md` nazariya va vazifalar, kod `sql/NN-nom/main.sql` (yoki `task_N.sql` fayllari) va ixtiyoriy `test.sql` (pgTAP). Asosiy DB PostgreSQL 18: `make sql n=05`. Dialekt vazifalarida (har darsda "Dialekt" guruhi bor) bir xil so'rovni boshqa DB'da ishga tushirasiz: `make sql n=05 db=mysql`, `db=mssql`, `db=oracle`, `db=sqlite`; buning uchun vazifa fayli dialekt bo'yicha nomlanadi (`task_N.mysql.sql`, `task_N.mssql.sql`, `task_N.oracle.sql`, `task_N.sqlite.sql`), runner `db` ga mos faylni tanlaydi. Namuna sxemalar `sql/docs/schema/` da (Claude yozadi): `shop.sql` (onlayn do'kon: customers, products, orders, order_items), keyingi darslarda `hr.sql` (xodimlar ierarxiyasi), `events.sql` (vaqt qatori, sessiya va gaps-and-islands uchun). Har dars boshida sxema `\i` (psql) yoki `make reset db=postgres` bilan qayta yuklanadi. Lint: `make lint` (sqlfluff, dialekt fayl nomidan aniqlanadi), `make check` topshirishdan oldin toza bo'lishi shart.

## I bosqich: Asoslar
1. **SQL asoslari va muhit**: SQL tarixi (SEQUEL, System R, Oracle V2 1979, SQL-86/89/92, SQL:1999 rekursiya va trigger, SQL:2003 window va MERGE, SQL:2011 temporal, SQL:2016 JSON va row pattern recognition, SQL:2023 `ANY_VALUE`, JSON tipi, property graph SQL/PGQ), standart va dialekt nima, deklarativlik (nima kerak, qanday emas), SQL tili bo'limlari (DDL, DML, DQL, DCL, TCL), relational asos qisqacha (jadval = relation, qator = tuple, bag semantikasi), klient asboblari (`psql` meta-buyruqlari `\d`, `\dt`, `\x`, `\timing`, `\i`, `\e`; DBeaver; `mysql`, `sqlcmd`, `sqlplus`/SQLcl, `sqlite3`), birinchi jadval, `INSERT`, `SELECT`, SELECT'ning logical processing order (`FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `DISTINCT` → `ORDER BY` → `OFFSET/FETCH`), asosiy tiplar, NULL va 3VL kirish, kommentlar, identifikator va qo'shtirnoq qoidalari, sqlfluff
2. **DDL: sxema va jadvallar**: database, schema, `search_path` (PostgreSQL), `CREATE TABLE` to'liq sintaksisi, `CREATE TABLE ... AS` va `LIKE`, `ALTER TABLE` (ustun qo'shish/o'chirish/nomini o'zgartirish/tipini o'zgartirish, `USING`), `DROP ... CASCADE`/`RESTRICT`, `TRUNCATE` vs `DELETE`, `IF [NOT] EXISTS`, temporary jadval (`ON COMMIT DROP/DELETE ROWS`), unlogged jadval qisqacha, generated column (`GENERATED ALWAYS AS (...) STORED`, PostgreSQL 18 `VIRTUAL`), DDL tranzaksiyaviyligi va vendor farqi, katalog (`information_schema` standart va `pg_catalog`), nomlash konventsiyalari (snake_case, birlik/ko'plik bahsi), DDL'ni migratsiya fayllarida saqlash (chuqur: `../ops/docs/00-reja.md`)
3. **Ma'lumot tiplari**: butun sonlar (`SMALLINT`, `INTEGER`, `BIGINT`) va overflow, `NUMERIC(p,s)`/`DECIMAL` vs `REAL`/`DOUBLE PRECISION` (pul uchun nega faqat `NUMERIC`), `CHAR(n)` vs `VARCHAR(n)` vs `TEXT` (padding tuzog'i), `BOOLEAN`, sana-vaqt tiplari kirish (`DATE`, `TIME`, `TIMESTAMP`, `TIMESTAMP WITH TIME ZONE`, `INTERVAL`), `UUID` (v4 vs v7, PostgreSQL 18 `uuidv7()`), binar (`BYTEA`/`BLOB`/`VARBINARY`), `CAST` va `::`, implicit va explicit tip o'zgarishi, tip ustunlik qoidalari, Oracle'ning `NUMBER`/`VARCHAR2`/`DATE` (vaqt bilan!), SQL Server `DATETIME2`/`NVARCHAR`, SQLite type affinity (dinamik tiplash, `STRICT` jadval), har tip uchun xotira o'lchami va to'g'ri tanlash qoidalari
4. **Constraintlar va yaxlitlik**: `NOT NULL`, `DEFAULT`, `PRIMARY KEY`, `UNIQUE` (NULL'lar bilan xulq va `NULLS NOT DISTINCT` PostgreSQL 15+), `CHECK` (ustun va jadval darajasida), `FOREIGN KEY` (`ON DELETE`/`ON UPDATE`: `CASCADE`, `SET NULL`, `SET DEFAULT`, `RESTRICT`, `NO ACTION` farqi), kompozit kalitlar, self-referencing FK, nomlangan constraintlar (`CONSTRAINT chk_...`), `DEFERRABLE INITIALLY DEFERRED` va qachon kerak (sikl FK), `EXCLUDE` (PostgreSQL, range overlap), `ALTER TABLE ... ADD CONSTRAINT ... NOT VALID` + `VALIDATE`, domain (`CREATE DOMAIN`), constraint vs ilova validatsiyasi (nega ikkalasi ham), MySQL'da `CHECK` faqat 8.0.16+, SQLite'da FK default o'chiq (`PRAGMA foreign_keys`)
5. **DML: INSERT, UPDATE, DELETE**: `INSERT ... VALUES` ko'p qator, `INSERT ... SELECT`, `DEFAULT VALUES`, ustun ro'yxatini doim yozish qoidasi, `UPDATE ... SET` ko'p ustun va row-value (`SET (a, b) = (...)`), `UPDATE ... FROM` (PostgreSQL/SQL Server) vs `UPDATE` + JOIN (MySQL) vs korrelyatsiyalangan subquery (Oracle/standart), `DELETE ... USING` vs `DELETE` + JOIN, `WHERE` siz `UPDATE`/`DELETE` xavfi va himoya (`safe_updates` MySQL, tranzaksiya ichida tekshirish), `RETURNING` kirish, `TRUNCATE ... RESTART IDENTITY`, katta hajmli DML'ni batch'larga bo'lish, DML va trigger/constraint tartibi
6. **SELECT, filtr va NULL**: `SELECT` ro'yxati, alias (`AS`) va alias ko'rinish doirasi (nega `WHERE` da alias ishlamaydi), `DISTINCT` va `DISTINCT ON` (PostgreSQL), solishtirish operatorlari, `BETWEEN` (inklyuziv, sana bilan tuzoq), `IN`, `LIKE`/`ILIKE` va escape, `IS [NOT] NULL`, `IS [NOT] DISTINCT FROM`, 3VL to'liq (`AND`/`OR`/`NOT` jadvali, `WHERE` faqat TRUE'ni o'tkazadi, `CHECK` esa UNKNOWN'ni ham o'tkazadi), `COALESCE`, `NULLIF`, `CASE` (simple va searched), operator ustunligi va qavslar, `ORDER BY` (`NULLS FIRST/LAST`, ustun raqami bilan, ifoda bilan), `LIMIT/OFFSET` va `FETCH FIRST ... ## II bosqich: So'rov yozish
8. **JOIN turlari va semantikasi**: Cartesian product (`CROSS JOIN`), `INNER JOIN` (`ON` vs `USING` vs `NATURAL` va nega `NATURAL` xavfli), `LEFT/RIGHT/FULL OUTER JOIN`, outer join'da `ON` va `WHERE` farqi (eng ko'p uchraydigan xato), self-join, ko'p jadvalli JOIN va tartib, non-equi join (range join, `BETWEEN` bilan), semi-join (`EXISTS`/`IN`) va anti-join (`NOT EXISTS`, `LEFT JOIN ... IS NULL`, `NOT IN` NULL tuzog'i), JOIN natijasida qator ko'payishi (fan-out) va aggregatni buzishi, eski uslub vergulli join va Oracle `(+)`, MySQL'da `FULL OUTER JOIN` yo'qligi va `UNION` bilan emulyatsiya, JOIN'ni Venn diagramma bilan emas, qatorlar ko'paytmasi bilan tushunish
9. **Aggregatsiya va GROUP BY**: aggregat funksiyalar (`COUNT(*)` vs `COUNT(col)` vs `COUNT(DISTINCT col)`, `SUM`, `AVG`, `MIN`, `MAX`) va NULL xulqi (bo'sh to'plamda `SUM` NULL qaytaradi), `GROUP BY` qoidasi (funksional bog'liqlik, PostgreSQL PK bo'yicha guruhlash, MySQL `ONLY_FULL_GROUP_BY`), `HAVING` vs `WHERE`, `FILTER (WHERE ...)` (standart, PostgreSQL) va `CASE` bilan conditional aggregation (boshqa vendorlarda), `STRING_AGG`/`LISTAGG`/`GROUP_CONCAT`, `ARRAY_AGG`, `BOOL_AND`/`EVERY`, `ANY_VALUE` (SQL:2023), statistik aggregatlar (`STDDEV`, `VAR_POP`, `CORR`, `REGR_*`), ordered-set aggregat (`PERCENTILE_CONT`, `PERCENTILE_DISC`, `MODE() WITHIN GROUP`), aggregat ichida `DISTINCT` va `ORDER BY`
10. **GROUPING SETS, ROLLUP, CUBE**: ko'p darajali hisobot muammosi va `UNION ALL` bilan yechimning narxi, `GROUPING SETS`, `ROLLUP` (ierarxik jami: yil, oy, kun), `CUBE` (barcha kombinatsiyalar), `GROUPING()` funksiyasi va subtotal qatorini haqiqiy NULL'dan ajratish, `GROUPING_ID`, kompozit va aralash grouping, MySQL `WITH ROLLUP` sintaksisi, SQL Server/Oracle'da to'liq qo'llab-quvvatlash, hisobot formatlash (`COALESCE(GROUPING(...))` bilan "Jami" yorlig'i), OLAP cube g'oyasiga ko'prik
11. **Subquery**: skalyar subquery (bitta qiymat, ko'p qator qaytarsa xato), qator va jadval subquery, `FROM` dagi derived table (alias majburiy), `IN`/`NOT IN`/`EXISTS`/`NOT EXISTS`, `ANY`/`SOME`/`ALL`, correlated subquery va uning bajarilish semantikasi (har qator uchun, optimizer esa uni join'ga aylantiradi), subquery vs JOIN qachon qaysi biri, `SELECT` ro'yxatidagi correlated subquery narxi, `LATERAL` (PostgreSQL/MySQL/Oracle) va `CROSS APPLY`/`OUTER APPLY` (SQL Server/Oracle) bilan "har guruh uchun top-N" va set-returning funksiyalar, `NOT IN` + NULL tuzog'ining 3VL orqali isboti
12. **Set amallar**: `UNION` vs `UNION ALL` (dublikat olib tashlash narxi), `INTERSECT`, `EXCEPT` (Oracle 21c gacha `MINUS`), `ALL` variantlari (`INTERSECT ALL`, `EXCEPT ALL`), ustunlar soni va tip moslik qoidalari, `ORDER BY` va `LIMIT` set amalda qayerda qo'llanadi, ustunlik (`INTERSECT` `UNION` dan kuchliroq), set amallar bilan ikki jadvalni solishtirish (data diff), NULL'lar set amallarda "teng" hisoblanishi (`WHERE` dan farqli), MySQL 8.0.31+ da `INTERSECT`/`EXCEPT`
13. **CTE (WITH)**: oddiy CTE va o'qilishi, bir nechta CTE zanjiri, CTE vs subquery vs view vs temporary jadval, materialization (PostgreSQL 12+ `MATERIALIZED`/`NOT MATERIALIZED`, eski versiyalarda optimization fence), CTE ichida DML (PostgreSQL data-modifying CTE: `WITH moved AS (DELETE ... RETURNING *) INSERT ...`), CTE va `RETURNING` bilan atomik ko'p bosqichli o'zgartirish, CTE nomi ko'rinish doirasi, SQL Server'da CTE oldidan `;`, MySQL 8.0+ dagi CTE
14. **Rekursiv CTE**: `WITH RECURSIVE` tuzilishi (anchor + recursive member, `UNION` vs `UNION ALL`), daraxt (xodim va menejer ierarxiyasi, kategoriyalar), yo'l (path) qurish va chuqurlik (`depth`), sikl aniqlash (standart `CYCLE` va `SEARCH DEPTH/BREADTH FIRST` PostgreSQL 14+, qo'lda array bilan), graf bo'ylab yurish (eng qisqa yo'l kichik grafda), sonlar va sana qatorlarini generatsiya qilish (`generate_series` alternativasi), bill of materials (BOM), cheksiz rekursiya himoyasi (SQL Server `MAXRECURSION`), Oracle `CONNECT BY` (`PRIOR`, `LEVEL`, `SYS_CONNECT_BY_PATH`) bilan solishtirish, adjacency list vs nested set vs closure table vs materialized path (`ltree`) modellari

## III bosqich: Analitik SQL
15. **Window functions I: asoslar va ranking**: window function nima va `GROUP BY` dan farqi (qatorlar yo'qolmaydi), `OVER ()`, `PARTITION BY`, `ORDER BY` window ichida, ranking: `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `NTILE`, `PERCENT_RANK`, `CUME_DIST`, deterministik bo'lmagan `ROW_NUMBER` tuzog'i (tie-breaker), window function'ni `WHERE` da ishlatib bo'lmasligi va subquery/CTE bilan filtr (`QUALIFY` faqat ba'zi DB'larda: DuckDB, Snowflake, BigQuery), logical order'dagi o'rni, named window (`WINDOW w AS (...)`)
16. **Window functions II: offset va aggregat**: `LAG`/`LEAD` (offset va default bilan), `FIRST_VALUE`/`LAST_VALUE`/`NTH_VALUE` va `LAST_VALUE` frame tuzog'i, aggregat window'lar (`SUM(...) OVER`, `AVG`, `COUNT`), running total, moving average, foiz ulushi (`x / SUM(x) OVER ()`), oldingi davr bilan solishtirish (MoM, YoY), `IGNORE NULLS` (Oracle, SQL Server 2022, Snowflake; PostgreSQL'da emulyatsiya), window function'lar ichma-ich bo'la olmasligi va qatlamlab yozish
17. **Window functions III: frame chuqur**: frame tushunchasi, `ROWS` vs `RANGE` vs `GROUPS` (PostgreSQL 11+), `UNBOUNDED PRECEDING`, `n PRECEDING`, `CURRENT ROW`, `n FOLLOWING`, default frame (`ORDER BY` bo'lsa `RANGE UNBOUNDED PRECEDING AND CURRENT ROW`) va dublikat qiymatlarda kutilmagan natija, `RANGE` bilan interval (`RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW`), `EXCLUDE CURRENT ROW/GROUP/TIES/NO OTHERS`, frame'ning unumdorlikka ta'siri, vendorlar bo'yicha frame qo'llab-quvvatlash jadvali, row pattern recognition (`MATCH_RECOGNIZE`, Oracle va Snowflake) qisqacha
18. **Pivot va unpivot**: qatorlarni ustunlarga aylantirish: conditional aggregation (portativ usul), `FILTER`, PostgreSQL `crosstab` (`tablefunc`), SQL Server va Oracle `PIVOT`/`UNPIVOT` operatorlari, dinamik ustunlar muammosi (dinamik SQL kerak, vendor modulida), unpivot: `UNION ALL`, `LATERAL (VALUES ...)`, `CROSS APPLY (VALUES ...)`, `UNPIVOT`, JSON orqali unpivot, keng va uzun (wide vs long) format va qachon qaysi biri (BI vositalari, data engineering)
19. **Sana, vaqt va timezone**: `DATE`, `TIME`, `TIMESTAMP` vs `TIMESTAMPTZ` (PostgreSQL'da `timestamptz` UTC saqlaydi va sessiya `TimeZone` bo'yicha ko'rsatadi), `AT TIME ZONE` ning ikki yo'nalishi, IANA timezone nomlari va DST tuzoqlari (mavjud bo'lmagan va ikki marta keladigan soat), `INTERVAL` arifmetikasi (oy oxiri: `'2024-01-31' + INTERVAL '1 month'`), `DATE_TRUNC`, `EXTRACT`/`DATE_PART`, `generate_series` bilan kalendar, haftaning birinchi kuni va ISO hafta, ikki sana orasidagi farq (`AGE`, `DATEDIFF` vendor farqlari), sana bo'yicha half-open interval qoidasi (`>= start AND < end`), MySQL `DATETIME` vs `TIMESTAMP` (2038 muammosi), SQL Server `DATETIMEOFFSET`, Oracle `DATE` ichida vaqt borligi, eng yaxshi amaliyot: UTC saqlash, ko'rsatishda konvertatsiya
20. **String, pattern va regex**: `SUBSTRING`, `LEFT`/`RIGHT`, `LPAD`/`RPAD`, `SPLIT_PART`, `STRING_TO_ARRAY`/`STRING_SPLIT`, `TRANSLATE`, `INITCAP`, `REVERSE`, `FORMAT`, collation (registr va urg'uga sezgirlik, ICU collation PostgreSQL, `COLLATE` ifodasi, MySQL `utf8mb4_0900_ai_ci`, SQL Server `_CI_AS`), `LIKE` va indeks (`text_pattern_ops`), `SIMILAR TO` (standart), POSIX regex (`~`, `~*`, `REGEXP_LIKE`, `REGEXP_REPLACE`, `REGEXP_SUBSTR`, `REGEXP_COUNT`, `REGEXP_MATCHES`), Unicode va `length` vs `octet_length`, normalizatsiya (`NORMALIZE` PostgreSQL 13+), full-text search kirish (chuqur: vendor modullari va `../elasticsearch/docs/00-reja.md`)

## IV bosqich: Ma'lumot o'zgartirish va obyektlar
21. **Upsert, MERGE va RETURNING**: upsert muammosi va race condition (`SELECT` keyin `INSERT` noto'g'ri), PostgreSQL `INSERT ... 22. **View va materialized view**: view nima (saqlangan so'rov), view orqali xavfsizlik va abstraksiya, updatable view qoidalari va `WITH CHECK OPTION`, `INSTEAD OF` trigger kirish, `CREATE OR REPLACE VIEW` cheklovlari, view ustiga view (qatlamlar va unumdorlik), `security_barrier` va `security_invoker` (PostgreSQL 15+), materialized view (`CREATE MATERIALIZED VIEW`, `REFRESH ... CONCURRENTLY` va unique indeks talabi), SQL Server indexed view, Oracle materialized view (fast refresh, query rewrite), MySQL'da materialized view yo'qligi va jadval + event bilan emulyatsiya, qachon view, qachon materialized view, qachon jadval
23. **Sequence, identity va kalit generatsiyasi**: `CREATE SEQUENCE` (`START`, `INCREMENT`, `CACHE`, `CYCLE`), `nextval`/`currval`/`setval`, sequence tranzaksiyaviy emasligi va bo'shliqlar (gap) normal ekanligi, `GENERATED ALWAYS` vs `BY DEFAULT AS IDENTITY`, `serial` nega eskirgan, identity'ni qayta tiklash, ko'p qatorli insert'dan keyin ID olish (`RETURNING`, `SCOPE_IDENTITY()`, `LAST_INSERT_ID()`), UUID v4 vs v7 vs ULID vs Snowflake ID (vaqt bo'yicha tartib, indeks lokalligi, distributed generatsiya), natural vs surrogate key qarori (nazariya: `../theory/docs/00-reja.md` 8-mavzu)
24. **Tranzaksiya buyruqlari (TCL)**: `BEGIN`/`START TRANSACTION`, `COMMIT`, `ROLLBACK`, autocommit rejimi (klient va driver darajasida), `SAVEPOINT`, `ROLLBACK TO SAVEPOINT`, `RELEASE SAVEPOINT`, `SET TRANSACTION ISOLATION LEVEL` va `READ ONLY`, PostgreSQL'da xatodan keyin tranzaksiya "aborted" holati (`current transaction is aborted`), `SELECT ... FOR UPDATE`/`FOR SHARE`/`SKIP LOCKED`/`NOWAIT` kirish (navbat pattern'i), ikki sessiyada lost update'ni ko'rsatish va uni `FOR UPDATE` yoki atomik `UPDATE ... SET x = x + 1` bilan tuzatish, vendorlarda DDL va implicit commit, nazariya chuqur: `../theory/docs/00-reja.md` III bosqich
25. **DCL: foydalanuvchi, rol va ruxsatlar**: user vs role (PostgreSQL'da bir xil), `CREATE ROLE ... LOGIN`, `GRANT`/`REVOKE` (obyekt va ustun darajasida), `WITH GRANT OPTION`, rol a'zoligi va meros (`INHERIT`, `SET ROLE`), `PUBLIC` psevdo-rol va `public` sxema ruxsatlari (PostgreSQL 15 o'zgarishi), `ALTER DEFAULT PRIVILEGES`, least privilege tamoyili (ilova uchun alohida rol: faqat DML, migratsiya uchun alohida), row-level security kirish (`CREATE POLICY`, chuqur: `postgres`), MySQL `'user'@'host'`, SQL Server login vs user vs schema, Oracle user = schema, `information_schema.table_privileges` bilan audit
26. **Indeks DDL va EXPLAIN kirish**: `CREATE INDEX` (oddiy, kompozit, `UNIQUE`, partial `WHERE`, expression indeks, `INCLUDE` covering), `CREATE INDEX CONCURRENTLY`, `DROP INDEX`, indeks qachon ishlatiladi va qachon yo'q (sargable predikat, funksiya ustida, `LIKE '%x'`, tip mos kelmasligi, past selektivlik), `EXPLAIN` va `EXPLAIN ANALYZE` (PostgreSQL 18'da `BUFFERS` default) chiqishini o'qish: Seq Scan, Index Scan, Index Only Scan, Bitmap Heap Scan, Nested Loop, Hash Join, Merge Join, Sort, rows estimate vs actual, `ANALYZE` va statistika, vendor ekvivalentlari (`EXPLAIN FORMAT=TREE`/`EXPLAIN ANALYZE` MySQL, SQL Server actual execution plan, Oracle `DBMS_XPLAN.DISPLAY_CURSOR`), chuqur: har vendor modulining tuning bosqichi va `../theory/docs/00-reja.md` IV–V

## V bosqich: Pattern'lar va sifat
27. **JSON va semi-strukturali ma'lumot**: SQL/JSON standarti (SQL:2016, SQL:2023 `JSON` tipi), PostgreSQL `json` vs `jsonb`, operatorlar (`->`, `->>`, `#>`, `@>`, `?`), `jsonb_path_query` va SQL/JSON path tili (`$.items[*] ? (@.price > 10)`), standart funksiyalar `JSON_VALUE`, `JSON_QUERY`, `JSON_EXISTS`, `JSON_OBJECT`, `JSON_ARRAYAGG`, `JSON_TABLE` (PostgreSQL 17+, MySQL, Oracle) bilan JSON'ni qatorlarga yoyish, `IS JSON`, vendor farqlari (MySQL `->>`/`JSON_EXTRACT`, SQL Server `OPENJSON`/`FOR JSON` va 2025'dagi `json` tipi faqat aniq bo'lsa, Oracle `JSON` tipi 21c+ va JSON-relational duality 23ai), qachon JSON ustun va qachon normal jadval, GIN indeks kirish
28. **Gaps-and-islands**: muammo ta'rifi (ketma-ket qiymatlar guruhlari: ketma-ket kirish kunlari, uzluksiz ish holati, ID'lardagi bo'shliqlar), `ROW_NUMBER` farqi usuli (`value - ROW_NUMBER()`), `LAG` + o'zgarish bayrog'i + `SUM() OVER` bilan guruh raqami (eng universal usul), sana bilan islands (`date - ROW_NUMBER() * INTERVAL '1 day'`), gap'larni topish (`LEAD` bilan), `generate_series` bilan to'liq kalendar va LEFT JOIN, overlapping interval'larni birlashtirish (interval merge), streak (eng uzun ketma-ketlik), unumdorlik va indeks
29. **Top-N, running total va dedup pattern'lari**: top-N per group (`ROW_NUMBER` + filtr, `LATERAL` + `LIMIT`, `DISTINCT ON`, `RANK` bilan teng qiymatlar), har guruhda eng oxirgi yozuv (latest row per key), running total va cumulative distinct, moving window aggregat, dublikatlarni topish (`GROUP BY ... HAVING COUNT(*) > 1`) va o'chirish (`ctid`/`ROWID`/`ROW_NUMBER` bilan, PK bo'lmagan jadvalda), "birinchi marta ko'rilgan" (first touch), median va percentile, pagination: offset vs keyset (seek) pagination (`WHERE (created_at, id) < ($1, $2) ORDER BY ... LIMIT`) va nega offset katta sahifada sekin
30. **Sessionization va vaqt qatori pattern'lari**: sessionization (30 daqiqalik bo'shliq bilan foydalanuvchi sessiyalari: `LAG` + yangi sessiya bayrog'i + `SUM() OVER`), funnel tahlili (qadamlar ketma-ketligi va konversiya), retention va cohort jadvali, churn, as-of join (har hodisa uchun o'sha paytdagi narx), SCD Type 2 jadvaldan "o'sha sanadagi" holatni olish, vaqt bucket'lari (`date_bin` PostgreSQL 14+), bo'sh davrlarni to'ldirish (gap filling, `generate_series` + LEFT JOIN + `LAG`/forward fill), data engineering'ga ko'prik (`../data-engineering/docs/00-reja.md`)
31. **SQL anti-patternlar**: Karwin "SQL Antipatterns" (2-nashr) asosida: jaywalking (vergul bilan ajratilgan ro'yxat ustunda), naive trees, ID required, keyless entry (FK yo'q), EAV, polymorphic associations, multicolumn attributes, metadata tribbles (jadval/ustun nomida sana), rounding errors (`FLOAT` pul uchun), 31 flavors (`ENUM`/`CHECK` vs lookup jadval), fear of the unknown (NULL), ambiguous groups, `SELECT *`, implicit columns in `INSERT`, random selection (`ORDER BY random()`), poor man's search engine (`LIKE '%x%'`), spaghetti query (bitta so'rovda hamma narsa), SQL injection (parametrlash, chuqur: `../app/docs/00-reja.md`), N+1 so'rov, har biriga yaxshi yechim
32. **SQL uslubi, o'qilishi va sqlfluff**: formatlash qoidalari (kalit so'zlar registri, indentatsiya, leading vs trailing comma, CTE bilan qatlamlash), nomlash (jadval, ustun, alias, constraint, indeks prefikslari), kommentlar, `sqlfluff` sozlash (`.sqlfluff`, dialekt, qoidalar: `LT`, `CP`, `AL`, `AM`, `RF`, `ST` guruhlari), `sqlfluff lint` va `fix`, pre-commit va CI'da lint, SQL kod review checklist'i, so'rovni test qilish (kichik fixture jadval, kutilgan natija bilan solishtirish, pgTAP `results_eq`), Simon Holywell "SQL Style Guide" va GitLab/Mozilla uslub qo'llanmalari

## VI bosqich: Yakun
33. **Procedural SQL'ga kirish**: deklarativ SQL qayerda tugaydi (shart va sikl, ko'p bosqichli biznes logika, xato boshqaruvi), SQL/PSM standarti (ISO 9075-4: `CREATE PROCEDURE`, `CREATE FUNCTION`, `BEGIN ... END`, `DECLARE`, `IF`, `WHILE`, `LOOP`, `CURSOR`, `HANDLER`), funksiya vs procedure farqi (qiymat qaytarish, tranzaksiya boshqaruvi, `CALL`), trigger tushunchasi (`BEFORE`/`AFTER`/`INSTEAD OF`, row vs statement), DB ichidagi logika vs ilova ichidagi logika bahsi (unumdorlik, xavfsizlik, testlash, versiyalash), bir xil kichik funksiyani to'rt vendorda yozib sintaksisni solishtirish, chuqur o'rganish joylari: PL/pgSQL `../postgres/docs/00-reja.md`, MySQL stored programs `../mysql/docs/00-reja.md`, T-SQL `../mssql/docs/00-reja.md`, PL/SQL `../oracle/docs/00-reja.md`
34. **Dialektlar ko'prigi: bir so'rov, besh DB**: portativ SQL yozish qoidalari, eng ko'p farq qiladigan joylar to'liq jadvali (pagination, identity, upsert, string birlashtirish, sana funksiyalar, boolean, bo'sh string, `LIMIT` subquery'da, `UPDATE ... JOIN`, rekursiv CTE kalit so'zi, `RETURNING`/`OUTPUT`, identifikator registri, collation), bitta murakkab hisobot so'rovini (CTE + window + aggregat) PostgreSQL, MySQL, SQL Server, Oracle, SQLite'ga o'tkazish va natijalarni solishtirish, ORM va query builder'lar dialektni qanday yashiradi va qachon yashira olmaydi, migratsiya asboblari (`pgloader`, AWS SCT, `ora2pg`) qisqacha
35. **Intervyu tayyorgarligi va yakuniy amaliyot**: SQL intervyu savollari turlari (yozma so'rov, natijani bashorat qilish, optimizatsiya, sxema dizayni), klassik masalalar (ikkinchi eng katta maosh, N-chi maosh, menejerdan ko'p oladigan xodimlar, ketma-ket 3 kun, foydalanuvchi retention, median), vaqt cheklovi bilan yechish, natijani tushuntirish, LeetCode Database va "SQL 50" ro'yxati (`../problems/docs/00-reja.md`), DataLemur, StrataScratch, HackerRank SQL, yakuniy ish: `shop` + `events` sxemalari ustida 20 ta biznes savoliga hisobot to'plami (CTE, window, rollup, gaps-and-islands, sessionization), har birida `EXPLAIN ANALYZE` va izoh
