# Oracle Database rejasi: arxitekturadan PL/SQL va ekspluatatsiyagacha

Nima uchun alohida va nima uchun chuqur: Oracle bank, telekom, davlat tizimlari va yirik korxonalarda (ERP, billing, core banking) hamon asosiy DB. O'zbekistondagi banklar, soliq va bojxona tizimlari, yirik telekom operatorlarida Oracle va PL/SQL bilimi to'g'ridan-to'g'ri ish o'rni. Oracle'ning o'ziga xos tomoni: biznes mantiqning katta qismi DB ichida, PL/SQL package'larida yashaydi. Shuning uchun bu rejada PL/SQL bitta mavzu emas, butun bir bosqichlar zanjiri (IV–VII). Oracle'ni tushunish boshqa DBlarni ham chuqurroq tushunishga yordam beradi: read consistency (undo), cost-based optimizer, partitioning, materialized view kabi g'oyalarning ko'pi sanoatda birinchi bo'lib shu yerda paydo bo'lgan.

Boshlash: `theory/` I–III bosqich (relational model, tranzaksiya, indeks nazariyasi) va `sql/` I–IV bosqich (standart SQL: JOIN, aggregatsiya, window function, CTE). PostgreSQL rejasining I bosqichi tanish bo'lsa, solishtirish osonroq. Standart SQL bu yerda takrorlanmaydi: faqat Oracle dialektidagi farq va qo'shimchalar.

Ishlash tartibi: `oracle/docs/NN-nom.md` nazariya va vazifalar, kod `oracle/NN-slug/main.sql` (yoki `task_N.sql`), testlar `test.sql` (utPLSQL). Muhit: `make up db=oracle` (Oracle Database 23ai Free, `gvenzl/oracle-free` image, Mac arm64 da ishlaydi, konteyner `ldb-oracle`, birinchi ishga tushishi 1–3 daqiqa), `make shell db=oracle` (SQL*Plus yoki SQLcl, `FREEPDB1` ga ulanadi), `make ora n=01` (`oracle/01-*/main.sql` ni ishga tushiradi), `make ora-test n=01` (utPLSQL testlari), `make reset db=oracle` (sxemani nolga qaytarish), `make check` (sqlfluff `oracle` dialekti bilan lint va barcha testlar). Kundalik IDE: VS Code uchun "Oracle SQL Developer Extension" yoki SQL Developer desktop.

Muhim: Oracle Free cheklovlari (2 CPU thread, 2 GB RAM, 12 GB user data) o'rganish uchun yetarli. RAC, Data Guard, GoldenGate, TDE kabi Enterprise Edition xususiyatlari Free'da yo'q yoki cheklangan: ular nazariya va diagnostika darajasida o'tiladi, mavzuda alohida belgilangan.

## I bosqich: Arxitektura va muhit

1. **Oracle arxitekturasi: instance va database**: instance (xotira + jarayonlar) va database (disk fayllari) farqi, nega bitta database'ni bir nechta instance ochishi mumkin (RAC g'oyasi), SGA tarkibi: database buffer cache (LRU, dirty buffer), shared pool (library cache: parse qilingan SQL va PL/SQL; data dictionary cache), redo log buffer, large pool, Java pool, In-Memory area; PGA (sort area, hash area, session xotirasi, `PGA_AGGREGATE_TARGET`); background jarayonlar: DBWn (dirty block'larni yozish), LGWR (redo yozish, commit qachon "tugaydi"), CKPT (checkpoint), SMON (instance recovery), PMON (o'lgan sessiyani tozalash), ARCn (redo arxivlash), MMON (AWR); dedicated vs shared server, listener va service name, `V$SGA`, `V$PROCESS`, `V$BGPROCESS`, PostgreSQL process modeli bilan solishtirish
2. **Fizik va logik tuzilma**: fizik: datafile, control file (DB "pasporti"), online redo log guruhlari va a'zolari, archived redo log, parameter file (`spfile` vs `pfile`), password file, alert log va trace fayllar (`ADR`, `adrci`); logik: tablespace (SYSTEM, SYSAUX, UNDO, TEMP, USERS), segment (table, index, undo, LOB), extent, data block (header, row directory, free space, PCTFREE), row chaining va row migration, ROWID tuzilishi (object#, file#, block#, row#), bigfile vs smallfile tablespace, `DBA_TABLESPACES`, `DBA_SEGMENTS`, `DBA_EXTENTS`, `DBA_DATA_FILES`, redo va undo nima uchun ikki xil narsa (redo: qayta bajarish, undo: bekor qilish va read consistency)
3. **Multitenant: CDB va PDB**: container database (CDB$ROOT), seed (PDB$SEED), pluggable database (`FREEPDB1`), common va local user (`C##` prefiksi), `ALTER SESSION SET CONTAINER`, `CON_ID` va `CDB_*` view'lar, PDB yaratish, clone, unplug/plug, resurs izolyatsiyasi, nega 21c dan non-CDB arxitektura yo'q, Free'dagi PDB soni cheklovi, multitenant'ning PostgreSQL "database" va SQL Server "database" tushunchasi bilan farqi
4. **Muhit: docker, SQL*Plus, SQLcl, SQL Developer**: `gvenzl/oracle-free` image (`ORACLE_PASSWORD`, `APP_USER`, init skriptlar `/container-entrypoint-initdb.d`), healthcheck, `docker logs` dagi "DATABASE IS READY", Easy Connect (`host:1521/FREEPDB1`), `tnsnames.ora` va TNS_ADMIN, SQL*Plus (`SET SERVEROUTPUT ON`, `SET LINESIZE`, `COLUMN ... QUOTA`, `GRANT DB_DEVELOPER_ROLE` 23ai), Oracle sample schemas (HR, SH, CO) o'rnatish
5. **Data dictionary va dinamik view'lar**: `USER_`/`ALL_`/`DBA_`/`CDB_` qatlamlari va farqi, `DICTIONARY` view orqali qidirish, `USER_TABLES`, `USER_TAB_COLUMNS`, `USER_CONSTRAINTS`/`USER_CONS_COLUMNS`, `USER_INDEXES`/`USER_IND_COLUMNS`, `USER_OBJECTS` (status `INVALID`), `USER_SOURCE` (PL/SQL manbasi), `USER_DEPENDENCIES`, `USER_ERRORS`, `V$` va `GV$` view'lar (`V$SESSION`, `V$SQL`, `V$LOCK`, `V$PARAMETER`, `V$INSTANCE`, `V$DATABASE`, `V$VERSION`), `X$` jadvallar haqida bir og'iz, `DBMS_METADATA.GET_DDL` bilan obyekt DDL'ini olish, dictionary'dan avtomatik hujjat va migration skript generatsiya qilish

10. **PIVOT, UNPIVOT, MODEL va MATCH_RECOGNIZE**: `PIVOT (SUM(x) FOR col IN (...))` va dinamik pivot muammosi (`PIVOT XML`), `UNPIVOT INCLUDE NULLS`, `MODEL` clause (dimension, measure, rule, spreadsheet uslubidagi hisob, `ITERATE`, qachon foydali va nega kam ishlatiladi), `MATCH_RECOGNIZE` (row pattern matching: `PARTITION BY`, `ORDER BY`, `MEASURES`, `PATTERN` regex, `DEFINE`, `ONE ROW PER MATCH`/`ALL ROWS PER MATCH`, `AFTER MATCH SKIP`), V-shaklli narx, sessionization, ketma-ket o'sish trendlarini topish misollari

27. **Records va collections I: tiplar**: record type (`TYPE r IS RECORD`, `%ROWTYPE` bilan, ichma-ich record, record bilan `INSERT`/`UPDATE ... SET ROW`), associative array (`INDEX BY PLS_INTEGER`/`VARCHAR2`, sparse, faqat PL/SQL'da, hash map sifatida), nested table (SQL tipi bo'la oladi, ustunda saqlash, `STORE AS`), `VARRAY` (cheklangan, tartibli), qaysi biri qachon (jadval), qualified expressions (18c, `t_list(1 => 'a', 2 => 'b')`), SQL-level type (`CREATE TYPE ... AS TABLE OF`) vs package-level type va 12c dan package tiplarni SQL'da ishlatish
28. **Collections II: metodlar va MULTISET**: `COUNT`, `FIRST`/`LAST`/`NEXT`/`PRIOR` (sparse collection'da to'g'ri iteratsiya), `EXISTS`, `EXTEND`, `TRIM`, `DELETE`, `LIMIT`, `COLLECTION_IS_NULL` va `SUBSCRIPT_BEYOND_COUNT` xatolari, `TABLE()` operatori bilan collection'ni SQL'da so'rash, `MULTISET UNION/INTERSECT/EXCEPT [DISTINCT]`, `MEMBER OF`, `SUBMULTISET`, `SET()`, `CARDINALITY`, `IS A SET`, `CAST(MULTISET(SELECT ...) AS t_list)`, `COLLECT` agregati, collection'ni ilovaga uzatish (array bind), xotira narxi va PGA
29. **BULK COLLECT va FORALL**: context switch muammosi raqamlar bilan (100k qator: loop vs bulk), `SELECT ... BULK COLLECT INTO`, `FETCH ... BULK COLLECT INTO ... LIMIT n` (PGA nazorati, to'g'ri chiqish sharti `EXIT WHEN l_tab.COUNT = 0`), `FORALL i IN 1..n` (bitta DML, ko'p bind), `FORALL ... INDICES OF`/`VALUES OF` sparse uchun, `SAVE EXCEPTIONS` va `SQL%BULK_EXCEPTIONS` (`ERROR_INDEX`, `ERROR_CODE`), `SQL%BULK_ROWCOUNT`, `RETURNING BULK COLLECT INTO`, bulk vs sof SQL (`INSERT ... SELECT`): avval SQL, keyin bulk, oxirida loop qoidasi, ETL uslubidagi bulk pipeline
30. **Dynamic SQL**: qachon kerak (DDL, runtime'da noma'lum jadval/ustun, dinamik filtr), `EXECUTE IMMEDIATE` (`INTO`, `USING`, `RETURNING INTO`, `BULK COLLECT INTO`), bind variable va nega literal konkatenatsiya yomon (hard parse, shared pool, injection), `OPEN FOR` dinamik, `DBMS_SQL` (noma'lum ustunlar soni: `PARSE`, `BIND_VARIABLE`, `DEFINE_COLUMN`, `DESCRIBE_COLUMNS`, `EXECUTE`, `FETCH_ROWS`, `TO_REFCURSOR`/`TO_CURSOR_NUMBER`), SQL injection PL/SQL'da (dinamik `ORDER BY`, jadval nomi), `DBMS_ASSERT` (`SIMPLE_SQL_NAME`, `SQL_OBJECT_NAME`, `ENQUOTE_LITERAL`, `ENQUOTE_NAME`, `QUALIFIED_SQL_NAME`), whitelist yondashuvi, dinamik SQL'ni debug qilish (matnni log qilish)
31. **Triggerlar**: DML trigger: row-level (`FOR EACH ROW`, `:NEW`/`:OLD`, `WHEN` sharti) va statement-level, `BEFORE`/`AFTER`, `INSERTING`/`UPDATING('col')`/`DELETING` predikatlari, firing order va `FOLLOWS`/`PRECEDES`, `INSTEAD OF` trigger (view ustida), mutating table xatosi (`ORA-04091`) va nega paydo bo'ladi, compound trigger (`BEFORE STATEMENT`/`BEFORE EACH ROW`/`AFTER EACH ROW`/`AFTER STATEMENT` bo'limlari bilan mutating'ni yechish), system triggerlar (`AFTER LOGON`, `BEFORE DDL`, `AFTER SERVERERROR`, `ON SCHEMA`/`ON DATABASE`), audit trigger amaliyoti, trigger anti-patternlari (yashirin biznes mantiq, kaskadli trigger'lar, performance), qachon trigger o'rniga constraint yoki procedure API
32. **Tranzaksiya boshqaruvi PL/SQL'da va autonomous transactions**: statement-level atomicity va unhandled exception'da nima rollback bo'ladi, `SAVEPOINT` va qisman rollback, `PRAGMA AUTONOMOUS_TRANSACTION` (mustaqil tranzaksiya: xato logi, audit, sequence emulyatsiyasi), uning xavflari (deadlock o'zi bilan, `ORA-06519`, mantiqiy nomuvofiqlik), `SET TRANSACTION READ ONLY`/`ISOLATION LEVEL SERIALIZABLE`, `DBMS_LOCK.SLEEP` vs `DBMS_SESSION.SLEEP`, `DBMS_LOCK.REQUEST` bilan user lock (advisory lock analogi), commit chastotasi va "commit in loop" anti-patterni (ORA-01555 bilan bog'liqlik)
33. **Pipelined va polymorphic table functions**: table function (collection qaytaruvchi funksiyani `FROM TABLE(f())` da), pipelined (`PIPELINED`, `PIPE ROW`, `RETURN;`, xotira tejash, birinchi qator tez), `PARALLEL_ENABLE (PARTITION ... BY ...)` va `CLUSTER`/`ORDER` bilan parallel pipelined, `NO_DATA_NEEDED` exception, ETL transformatsiya zanjiri sifatida, polymorphic table functions (18c: `DBMS_TF`, `DESCRIBE` va `FETCH_ROWS`, istalgan jadval ustidan ishlaydigan funksiya), table SQL macro (21c) bilan solishtirish
34. **Object types va obyektga yo'naltirilgan PL/SQL**: `CREATE TYPE ... AS OBJECT` (atributlar, `MEMBER`/`STATIC` metodlar, `CONSTRUCTOR`, `MAP`/`ORDER` metodlar taqqoslash uchun), `TYPE BODY`, meros (`NOT FINAL`, `UNDER`, `OVERRIDING`, `NOT INSTANTIABLE`), `TREAT` va `IS OF`, object table va `REF`, object view, type evolution (`ALTER TYPE ... CASCADE`) va uning og'riqlari, `ANYDATA`/`ANYTYPE`, amaliyotda qayerda ishlatiladi (collection elementi, API parametri) va nega object-relational modelda jadval saqlash kam uchraydi
35. **Huquqlar modeli, conditional compilation va compiler**: definer rights vs invoker rights (`AUTHID DEFINER`/`CURRENT_USER`), role'lar definer rights'da ishlamasligi (nega `GRANT` to'g'ridan-to'g'ri kerak), code-based access control (`GRANT role TO PROCEDURE`), `INHERIT PRIVILEGES`, conditional compilation (`$IF $$debug $THEN`, `$ERROR`, `PLSQL_CCFLAGS`, `DBMS_DB_VERSION`, `DBMS_PREPROCESSOR.PRINT_POST_PROCESSED_SOURCE`), compiler sozlamalari: `PLSQL_OPTIMIZE_LEVEL` (0–3, subprogram inlining), `PLSQL_CODE_TYPE = NATIVE` vs `INTERPRETED`, `PLSQL_WARNINGS = 'ENABLE:ALL'` va asosiy ogohlantirishlar (PLW-05005, PLW-06002, PLW-06009, PLW-07204), `USER_PLSQL_OBJECT_SETTINGS`, PL/Scope (`PLSCOPE_SETTINGS`, `USER_IDENTIFIERS`, `USER_STATEMENTS`) bilan kod tahlili, kodni yashirish (`WRAP`, `DBMS_DDL.WRAP`) va uning chegarasi
36. **Edition-based redefinition (EBR) va zero-downtime deploy**: muammo: `CREATE OR REPLACE PACKAGE` ishlab turgan tizimda library cache lock va `ORA-04068`, edition tushunchasi (`CREATE EDITION`, `ALTER SESSION SET EDITION`), editionable obyektlar, editioning view, cross-edition triggerlar (forward va reverse), ikki versiya parallel yashashi, `DBMS_PARALLEL_EXECUTE` bilan katta jadvalni bo'lib yangilash, online table redefinition (`DBMS_REDEFINITION`), zero-downtime migration strategiyalari va ularning PostgreSQL/MySQL'dagi analogi (expand/contract), real loyihada CI/CD bilan PL/SQL deploy (Liquibase/Flyway, SQLcl `project`)
37. **PL/SQL dizayn va arxitektura**: qatlamlar (data access package, business logic package, API package), "table API" (TAPI) va "transactional API" (XAPI) bahsi, Steven Feuerstein eng yaxshi amaliyotlari, xato boshqaruvi standarti (umumiy error package, Logger kutubxonasi), konfiguratsiya jadvali va package konstantalari, kod duplikatsiyasidan qochish, set-based fikrlashga qaytish, PL/SQL'ning zamonaviy ilova arxitekturasidagi o'rni (mikroservislar davrida qachon DB ichidagi mantiq o'zini oqlaydi, qachon yo'q)

## VII bosqich: Test, debug va DBMS paketlar

## VIII bosqich: Tranzaksiya, concurrency, optimizer va performance

41. **Read consistency, undo va locking**: multi-version read consistency undo orqali (SCN, consistent read block'larni qayta qurish), "readers don't block writers" va uning PostgreSQL MVCC'dan farqi, `ORA-01555 snapshot too old` (sabablari: uzun so'rov, kichik undo, commit in loop, delayed block cleanout), isolation darajalari (`READ COMMITTED`, `SERIALIZABLE`, `READ ONLY`) va `ORA-08177`, write consistency va statement restart, row-level lock (ITL slotlar, `INITRANS`, enq: TX - row lock contention), table lock rejimlari (RS, RX, S, SRX, X), `SELECT FOR UPDATE NOWAIT/WAIT/SKIP LOCKED` (queue pattern), deadlock (`ORA-00060`, trace fayl o'qish), lost update muammosi va optimistic locking (`ORA_ROWSCN`, version ustun), FK'da indeks yo'qligi lock'i, `V$LOCK`, `V$SESSION.BLOCKING_SESSION`, `DBA_BLOCKERS`
42. **Cost-based optimizer va execution plan**: parse bosqichlari (hard vs soft parse, shared pool, `V$SQL`, `SQL_ID`, child cursor), bind variable peeking va adaptive cursor sharing, `EXPLAIN PLAN` vs haqiqiy plan (`DBMS_XPLAN.DISPLAY_CURSOR(format => 'ALLSTATS LAST')`, `GATHER_PLAN_STATISTICS` hint), planni o'qish (operatsiyalar tartibi, E-Rows vs A-Rows, Buffers, Starts), access path'lar (full table scan, index range scan, index fast full scan), join metodlari (nested loops, hash join, sort merge, Cartesian), join order, query transformation (view merging, subquery unnesting, predicate pushing, star transformation), adaptive plans (12c), cardinality xatosining sababi va oqibati
43. **Statistika, hints va plan barqarorligi**: `DBMS_STATS.GATHER_TABLE_STATS`/`GATHER_SCHEMA_STATS` (`ESTIMATE_PERCENT => AUTO_SAMPLE_SIZE`, `METHOD_OPT`), histogram turlari (frequency, top-frequency, height-balanced, hybrid), extended statistics (column group, expression), stale statistics va avtomatik job, statistikani lock/export/import qilish, dynamic sampling, hints (`INDEX`, `FULL`, `LEADING`, `USE_NL`, `USE_HASH`, `PARALLEL`, `APPEND`, `NO_MERGE`, `QB_NAME`) va nega hint oxirgi chora, SQL Plan Management (SQL plan baseline: capture, evolve, `DBMS_SPM`), SQL profiles (SQL Tuning Advisor), SQL patch (`DBMS_SQLDIAG`), plan regression'ni tekshirish
44. **Performance diagnostikasi: AWR, ASH, wait events**: Oracle "time model" va DB time, wait event sinflari (User I/O, Concurrency, Commit, Application), asosiy eventlar (`db file sequential read`, `db file scattered read`, `log file sync`, `enq: TX - row lock contention`, `latch: shared pool`, `library cache lock`, `buffer busy waits`), `V$SESSION`, `V$SESSION_WAIT`, `V$ACTIVE_SESSION_HISTORY`, AWR snapshot va hisobot (`awrrpt.sql`, Diagnostics Pack litsenziyasi haqida ogohlantirish), ADDM, ASH report, SQL Monitor (`DBMS_SQL_MONITOR`, real-time), Statspack (Free uchun bepul alternativ), top SQL'ni topish (`V$SQLSTATS`), performance metodologiyasi (taxmin emas, o'lchov)
45. **Instance tuning va resurs boshqaruvi**: xotira parametrlari (`SGA_TARGET`, `PGA_AGGREGATE_TARGET`/`LIMIT`, `MEMORY_TARGET` va nega katta tizimda ishlatilmaydi), connection: dedicated server narxi, connection pool (DRCP, ilova tomonidagi pool), redo hajmi va `log file sync` (commit chastotasi), parallel execution (`PARALLEL` hint, DOP, PX server'lar, qachon zarar), Result Cache server tomonida, In-Memory Column Store qisqa (EE opsiyasi), Database Resource Manager, parametrlarni o'zgartirish (`ALTER SYSTEM SET ... SCOPE=BOTH/SPFILE`), `V$PARAMETER` va yashirin parametrlarga tegmaslik
46. **Performance bo'yicha amaliy laboratoriya**: sekin package'ni bosqichma-bosqich tezlashtirish: SQL trace bilan o'lchash, row-by-row'ni bulk'ga, bulk'ni sof SQL'ga o'tkazish, PL/SQL funksiyani SQL'dan olib tashlash (scalar subquery caching, `WITH FUNCTION`, SQL macro), indeks va statistika, plan baseline bilan barqarorlashtirish, natijalarni jadval bilan hujjatlash

## IX bosqich: Ilg'or ma'lumot tuzilmalari

47. **Partitioning**: nega (boshqaruv, partition pruning, parallel, arxivlash), range, list, hash, interval (avtomatik yangi partition), reference partitioning (FK bo'yicha), composite (range-hash, range-list, list-range), virtual column partitioning, automatic list partitioning, local vs global index (prefixed/non-prefixed, global index maintenance `UPDATE INDEXES`), partition amallari (`ADD`, `DROP`, `TRUNCATE`, `SPLIT`, `MERGE`, `EXCHANGE PARTITION` bilan tez yuklash, `MOVE ONLINE`), pruning'ni planda ko'rish (`PSTART`/`PSTOP`), partition-wise join, Free/EE litsenziya holati (23ai Free'da mavjudligini tekshirib ko'rish vazifasi), PostgreSQL declarative partitioning bilan solishtirish

51. **Xavfsizlik**: user va schema, authentication (parol, OS, Kerberos/LDAP qisqa), `PROFILE` (parol siyosati, `FAILED_LOGIN_ATTEMPTS`, resurs limitlari), system va object privilege, role (`CREATE ROLE`, default role, `SET ROLE`, password-protected role), `WITH ADMIN OPTION`/`WITH GRANT OPTION`, least privilege, schema-only account (`NO AUTHENTICATION`), schema privileges (23ai: `GRANT SELECT ANY TABLE ON SCHEMA hr TO ...`), `DB_DEVELOPER_ROLE` (23ai), Virtual Private Database (`DBMS_RLS.ADD_POLICY`, policy funksiya, application context `SYS_CONTEXT`/`DBMS_SESSION.SET_CONTEXT`), Real Application Security qisqa, Data Redaction (`DBMS_REDACT`, EE opsiyasi), TDE (tablespace va column encryption, wallet/keystore, EE opsiyasi, nazariy), Unified Auditing (`CREATE AUDIT POLICY`, `UNIFIED_AUDIT_TRAIL`), network encryption, SQL injection'dan himoya takrori (30-mavzu)
